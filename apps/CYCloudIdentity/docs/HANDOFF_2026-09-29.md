## 6. Employee lifecycle and highest authority

Implemented Employee flow:

1. highest authority creates pending Employee record with Employee No/name/Email;
2. administrator does not set or send a plaintext initial password;
3. Employee uses login-page activation;
4. Email OTP verifies the Email;
5. Employee sets their own first password;
6. account becomes enabled.

Implemented highest-authority transfer:

1. current highest authority chooses an enabled/verified/credential-ready target Employee;
2. current password re-auth;
3. OTP goes to the current authority verified Email;
4. confirm transfers the Workspace authority pointer;
5. Recovery Email follows the new authority verified Email;
6. previous authority sessions are revoked.

Backend protection in `0.1.13`: current highest authority cannot be directly disabled before transfer.

CY Web management UI:

- shows current highest authority and Recovery Email state;
- provides authority-transfer flow;
- does not offer a normal direct disable action for current highest authority in the currently deployed `0.1.49` correction.

## 7. Groups, Application Access and CYInvoice compatibility role

Ordinary Groups are extensible and data-driven. No fixed normal-role enum should be introduced.

Access sources:

- Group Application grant
- direct Employee Application grant
- protected highest-authority access

Compatibility-role mode is Application-specific, not a field hard-coded into generic Group identity.

`USER_ADMIN` effective projection:

- Workspace highest authority => `SUPER_ADMIN`
- any active Group grant with `ADMIN` => `ADMIN`
- otherwise active Group grant with `USER` => `USER`
- otherwise direct Application grant => `USER`
- otherwise no Application access

CYInvoice contract decision:

- effective precedence is `SUPER_ADMIN > ADMIN > USER`
- ordinary Groups may only set `USER` / `ADMIN`
- Groups can never grant `SUPER_ADMIN`
- direct access defaults to `USER`
- CYInvoice should consume Identity's effective `applicationRoleKey`; it should not reconstruct role precedence itself

Reference document: `docs/APPLICATION_ROLE_MAPPING.md`.
