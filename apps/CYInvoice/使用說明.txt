本工程版提供同機折讓申請、提出者撤回自己的待核准申請，以及主管一次核准與自動處理；Cloud模式的提出者詳情／撤回需配套Cloud0.9.15部署後生效。處理中內容為帳號、姓名及原因，詳情商品表有序號，折讓原因列於審核資訊；退回原因單行20字。確認退回成功後立即更新可折讓狀態，未知結果仍保留原申請。真人業務流程未全部驗收，跨機協同留下一版。升級仍須保留原安裝資料，版本內容見程式附帶的當版版本說明，延期驗收見「發行後待驗收.md」。

一、啟動與資料
1. 本程式適用 Windows 10/11 x64，請直接執行 CYInvoice.exe。啟動檢查在主視窗內顯示轉圈與文字，完成後自動收起，不另開提示視窗。
2. 第一次使用的兩種方式：
   (1) 使用單機版：建立這台電腦的本機超級管理員。
   (2) 直接加入雲端：使用配對碼，或邀請碼與既有超管帳密；沿用中央帳號，不建立本機帳號。
   單機版須建立超級管理員（4 碼員編、姓名、Email、至少 8 碼 ASCII 英數密碼），並妥善保存一次性復原碼。MO店+ Excel 密碼改為需要匯入時才設定。
3. 設定與發票紀錄存放於 Data；快取與既有紀錄存放於 Cache、Logs；目前問題診斷集中於程式同目錄 log。
4. 主要資料庫為 Data/CYInvoice.db；設定位於 Data/settings.json。升級時舊發票 JSON 由程式驗證後遷移並保留；請勿任意刪除或修改 Data。搬移時保留完整程式資料夾，受保護設定仍受原 Windows 使用者限制。

二、環境安全
1. 初次啟動固定使用光貿測試環境，不會開立正式發票。
2. 正式環境使用設定中的正式公司卡；CYID模式由授權裝置同步超管管理的卡片，Local在本機設定。切換／編輯仍須原員工與管理員驗證。
3. App Key 與 MO店+ 密碼使用 Windows DPAPI 加密，只能由原 Windows 使用者解密。
4. 正式開立前，務必再次確認畫面上方的環境提示。

三、手動開立
1. 選擇一般消費者或公司統編，輸入訂單編號、買方資料與商品明細。自動訂單編號格式為 MYYYYMMDDXXX。
2. 公司統編輸入完整 8 碼後會自動查詢買方名稱：先查本機人工記憶，再查光貿 API。若人工修改後與 API 名稱不同，買方名稱會以紅字提示，欄位右側會出現可點擊的 ↻ 供強制重新查詢 API。
3. 公司統編發票可切換含稅／未稅輸入；已有明細會自動換算到小數點後最多 7 位。
4. 品名按 Enter 移到數量，數量按 Enter 移到單價；單價按 Enter 後，會移至既有下一列品名，若目前是最後一列則自動新增明細並移到新品名。
5. 使用「預覽」核對內容，再按「開立測試發票」或「開立正式發票」。
6. 已成功訂單再次送出仍由光貿判定；收到重複錯誤會留下開立失敗紀錄，只在「上傳問題」顯示及清除，不影響原成功發票。結果不明時先回查原紀錄，請勿盲目重送。

四、Excel 匯入
1. MO店+、酷澎及鼎新 ERP 都會先開啟同一套開立發票匯入確認視窗；只有原始 Excel 表頭與取用欄位依平台不同。
2. 請逐張核對並勾選；取消、未勾選、資料有問題或尚未完成確認的訂單不會送出。
3. MO店+ 使用設定內保存的 Excel 密碼唯讀解析；未設定時先提示設定，不會先開選檔視窗。酷澎依已寄出 DeliveryList 欄位解析。
4. 鼎新 ERP 可直接匯入 .xlsx。活頁簿必須包含「單頭資料」與「單身資料」，且一個檔案只允許一張銷貨單：
   - 單頭使用銷貨單號、統一編號、客戶全名、本幣合計。
   - 單身使用品名、數量、金額；若有「單位」欄會一併傳送至光貿。
   - 金額是權威值，單價由金額 ÷ 數量推導；單身金額合計必須與單頭本幣合計一致。
5. 鼎新確認畫面可修正統一編號及買方名稱。完整 8 碼統編會使用與手動開票相同的自動查詢；修改後必須按「套用資料」才可開立。畫面會保留原始鼎新買方資料供核對。
6. 光貿測試環境送出時以專用技術訂單編號避免共享測試池撞號，畫面仍保留原始訂單編號供核對；客戶、商品、聯絡資料及備註會去識別化，本機確認畫面及紀錄仍保留原始內容。
7. 匯入確認的「檢查狀態」會直接顯示是否可開立；已有開立紀錄或結果不明時會禁止重送。

五、已開立發票清單
1. 預設查詢本月第一日至今天，可再依發票號碼、訂單、買受人、統編、來源與狀態篩選；來源包含手動、MO店+、酷澎及鼎新 ERP 等現行來源。
2. 「重新整理狀態」會向光貿查詢，不會改寫原送出時間，也不會自動重送結果不明的發票；按鈕右側會顯示「單擊發票號碼即可複製」。單擊清單中的發票號碼欄位會直接複製該號碼，並短暫顯示「✓ 已複製 XXXXXXXX」。
3. 舊版重複成功可用「重新整理狀態」修復：程式先回查光貿並備份到 Data/RepairBackups，只有同發票、訂單與明細且能確認送出先後時，才保留原成功，把多出的那筆移到上傳問題顯示開立失敗。不會向光貿作廢或重開；證據不足會保留原資料並提示問題。
4. 紙本與會員載具的詳細資訊視窗使用一致的精簡配置。紙本會顯示官方 A4 第一頁預覽；會員載具使用模擬電子發票與本機交易明細，不呼叫紙本 PDF API。
5. 「檢視 PDF」沿用 Edge PDF Viewer：一般消費者直接開啟完整 A4；公司統編會先顯示 A4 整張、A4（地址＋A5）、A4（A5 內容）、A5 或 QRcode_A4 五張示意卡片，選擇後才開啟對應的真實 PDF。A5 示意與直接列印均為橫式 210×148；縮圖中的白底即紙張本身，因此 A5 白底只佔 A4 高度約一半並位於上方。QRcode_A4 的票面區塊位於接近左上方，但不貼邊。
6. 「列印發票」會取得同一份官方 PDF 後直接送到 CYInvoice 記住的發票印表機，不開啟可見 PDF Viewer。直接列印只允許 Windows 回報支援雙面的印表機；選擇視窗只列出這些印表機。若要使用未回報雙面能力的印表機，請改用「檢視 PDF」後由 PDF Viewer 手動列印。
7. 一般消費者紙本固定以 A4、雙面、長邊翻轉直接列印；此設定只作用於 CYInvoice 當次列印，不修改 Windows 全域預設印表機。記住的印表機若不存在或不再回報雙面能力，程式會要求重新選擇，不會改送 Windows 預設印表機。
8. 公司統編使用「列印發票」時同樣先選五種官方版型，再直接送至記住的雙面印表機；公司列印沿用該印表機的 duplex 預設。
9. PDF 檢視視窗使用 Edge PDF Viewer 右上方原生工具列縮放、下載及手動列印。若畫面無法啟動，請確認 Windows 已安裝 Microsoft Edge WebView2 Runtime。
10. 會員載具沒有一般紙本 PDF；模擬票會明確標示非正式憑證；其一維條碼及兩個 QR Code 只固定連至光貿電子發票網站，不承載正式發票驗證資料。

六、作廢、折讓與處理清單
1. 發票作廢從原明細提出；紙本證明聯尚未收回時先由管理員處理人工確認，等待官方結果時勿重送。
2. 折讓申請分為既有折讓與本次商品兩區。商品固定顯示五列，超過可捲動；「重置」還原原商品。原因只供程式內部查閱，為單行且最多20字，旁邊顯示字數；折讓單號沿用既有格式。核對商品、金額及原因後，輸入員工帳密提交原待辦。主管一次核准後由程式連續處理，不需再次驗證或另按手動送出。
3. 折讓及折讓作廢只在主管核准前可填原因取消退回；核准成功後即停止提供退回、再次核准與送出操作。
4. 「處理中」顯示等待主管或官方處理；「上傳問題」顯示真正異常。結果不明只查回原ID／原號，不自行建立新申請、改號、解除Claim或重送。
5. 雙擊可讀取完整詳情及目前進度。折讓詳情分「原發票資訊」「本次折讓資訊」「審核資訊」三區，先核對原商品、原金額及本次折讓商品／金額，再執行審核；品項較多時可捲動，缺少原商品時明示資料未取得。單價與金額會標示含稅或未稅。同張折讓單歷程只列一筆，技術查證與執行事件留詳情。已知同機資料在光貿暫時無回應時仍可查看。
6. 只有符合條件的開立失敗紀錄可勾選清除；一般舊待辦結案不代表光貿成功，已送出或結果不明的財務案件不能直接標記完成。
7. 折讓PDF仍沿原官方查詢與檢視器；不存在的舊原因／人員不會由系統猜測補造。

七、雲端與帳號
1. 單機與雲端的帳號管理依目前模式使用本機或中央帳號；需要權限時才驗證，不持續登入。
2. 加入既有雲端只使用配對碼或邀請碼，先確認 Workspace 名稱；不要複製其他電腦 Data 來冒用裝置。
3. 雲端正常時權限操作採最新中央資料；雲端連線失敗、逾時或 503 暫時不可用且光貿正常時，沿用原有降級單機的最後可信快取。中央帳號與裝置異動仍須連線。
4. CYID 雲端帳號、Email 驗證與忘記密碼由 CYWEB／CYID 辦理；單機超管使用本機復原碼。兩者不是裝置 Token 復原。
5. 裝置管理直接顯示使用中的裝置。按「新增裝置」開啟配對／邀請視窗；按「更改裝置名稱」並輸入中央超管帳密可改名。撤銷紀錄仍保留雲端，只從程式清單隱藏。
   「使用版本」和「最後使用時間」會在該裝置每次啟動且成功連線回報後更新；時間顯示為本機時區。離線或舊版未回報可能顯示較舊版本，未回報的時間留白；不代表裝置目前仍在線。
6. 切回單機會要求兩次確認，安全退出目前裝置後清除這台安裝的本機資料，再回到首次使用；不影響其他裝置。結果不明時保留資料，待重新連線確認。

八、問題排查
1. 上方 API 狀態：灰色為查詢中、綠色為正常、紅色為異常。
2. 發生問題時請保留完整CYInvoice資料夾及log；問題診斷由程式自動記錄，可將log交維運查證。舊系統診斷／匯出診斷按鈕已退役；不要自行重送結果不明的發票。
3. 若下載正式 GitHub Release，請同時核對附帶的 SHA-256；Public 可下載不代表開放原始碼，授權仍以 LICENSE 為準。
4. 測試 Artifact 依套件內 `Channel: engineering` 中繼資料及 Artifact 名稱與正式包區分；版本標題不另加「工程測試包」。未經明確發布要求的版本不建立正式 Release。

CYID 帳號模式
1. 本版僅提供單機 Local 與 CYID Cloud；須由維運完成相容後端及裝置確認。舊 Built-in／Self-hosted 不在本版現役模式內，請保留原版本與資料，先由維運確認接續方式。
2. CYID 員工首次啟用、帳號管理、密碼重設由 CY Web 辦理；CYInvoice 隱藏帳號管理，不需要持續登入。
3. 操作時輸入 4 碼員編及 CYID 永久密碼（8～16 個 Unicode 字元）；每次在線確認最新使用權限。
4. 已成功在線驗證的員工，雲端連線失敗、逾時或 503 暫時不可用且光貿正常時，可沿用原裝置最後加密快取。重新連線後採最新權限；帳密錯誤、權限拒絕與裝置撤銷不能降級放行。
5. 實際雲端功能依維運部署與設定為準；安裝本程式不會自動遷移 D1、建立雲端資源或轉換舊帳號。

CYID 公司卡
1. 從「設定 → CYID 公司卡」以當次帳密驗證；超管可修改雲端公司統編、App Key 與 MO店+ 密碼，管理員可查狀態，一般使用者不可取得憑證。
2. 雲端「已設定」不等於每台電腦已套用。超管在公司卡對話選擇套用到這台電腦，核對統編與版次並再次明確確認後，才會覆寫這台電腦的正式憑證並以 DPAPI 保存。
3. 其他電腦須各自經超管授權套用；公司卡不自動覆寫本機設定，空白欄位也不代表清除既有秘密。結果不明先查回狀態，不盲目重送修改。

裝置災難復原
1. 一般新增電腦使用配對／邀請；只有舊裝置憑證全部遺失時，才使用公司級災難復原。
2. 由 CYWEB 超級管理員重新驗證並簽發短效邀請；新電腦從「加入雲端 → 災難復原」輸入目標、邀請碼及當次超管帳密，先核對原公司，再確認接管。
3. 成功接管會撤銷同公司所有其他舊裝置。舊安裝再次連線後可能依原撤銷流程清除該安裝本機資料；不要把此功能當一般新增裝置，也不要為測試撤銷唯一仍在使用的裝置。
4. 結果不明時保留原 Pending Token、原邀請與範圍，重開後查回同一次操作；不要重建 Token、盲目重簽或重送發票。
5. 裝置接管不等於整個雲端服務或本機未上雲資料還原；Local／單機資料由使用者自行保管，本版沒有單機常態災難備份。
6. 本 V3.1.0 已獲使用者正式發行批准。V3.0 真實 Email、異機不同金鑰災復，及 V3.1 雙 Windows／CYID 角色／高 DPI 等真人操作仍延期；未驗收不代表已通過。完整合併清單請看本發行包「發行後待驗收.md」，版本內容見 V3.1.0.txt。

V3.1 非折讓跨機待辦（V3.1.0 正式版）
1. Cloud CYID 模式的「上傳問題」可在人工確認後回報非折讓的 VOID／UPLOAD_ISSUE 例外；管理員可在「跨機待辦」查看、人工覆核及封存。
2. 待辦已封存不代表光貿已作廢／上傳成功；不會替使用者自動重送發票。回覆不明保留同一工作項目 ID，管理員可在待辦視窗使用「依 ID 查回」。
3. 本工程版的跨機待辦清單已改為隨視窗寬度分配欄位，減少最小尺寸下的水平溢出；仍須真人在 100／125／150% DPI 下核對可讀性。
4. 「回報跨機」只對尚未結案且 V3.1 支援的非折讓技術例外或紙本作廢待審項目可按；折讓／折讓作廢不屬於 3.1 範圍，已結案與未知問題類型亦不會開放。
5. 原CYInvoice目前已完成Cloud0.9.14／schema23配套；但兩台 Windows 與不同 CYID 角色的正向人工驗收仍延期，請勿將服務已切換當作所有實際流程已驗證。Local 模式不顯示 Cloud 待辦。
6. 本正式版使用者須知：跨機「人工封存」不代表光貿官方作廢或上傳成功；無法確認官方結果時須先回查，不可重送。未完成驗收項目均在「發行後待驗收.md」。

服務連線與操作
1. 光貿與雲端都正常：照常操作，使用目前權限。
2. 光貿正常、雲端暫時不可用：使用原有降級單機功能；中央帳號與裝置異動等待雲端恢復。
3. 光貿無法連線、雲端正常：開票、查詢、作廢、折讓確認、PDF 與背景同步暫停；雲端帳號與裝置功能仍可使用。
4. 兩者都無法連線：顯示阻擋提示，暫停全部業務功能。每 15 秒自動重新檢查，也可按「重新檢查」或「關閉程式」。任一服務恢復後依上述狀態繼續。
5. 純單機只檢查光貿；光貿無法連線時顯示同一阻擋提示，直到光貿恢復。
6. 中斷及恢復保留原 Workspace、裝置、Token、資料和輸入；不自動重送發票。結果不明仍先回查，再依既有流程處理。
