# CYAccountingWeb 平板介面規劃

日期：2026/10/03（日本時間）  
規劃基準：V0.22.1 Build 1，main `d822afd779642fbeae745d0f643c5d7d8fb1f1ab`  
狀態：需求與設計方向彙整；尚未實作平板新介面。

本文件是本次平板工作項目的規劃，不是永久規則來源。正式規則沿用根 REPOSITORY_RULES.md、REPO_POLICY.md 與本專案 PROJECT_RULES.md。本文不將尚待實機驗證的尺寸或互動提案視為已驗收功能。

## 1. 已確認的需求

- 平板提供直向與橫向兩種配置。
- 橫向參考電腦版的**左記帳、右看帳**左右分欄，不是上記帳、下看帳。
- 直向以大塊看帳區為主；使用者提出下方固定小塊記帳區，或可收合／展開的底部記帳欄。
- 觸控優先參考並共用手機版已完成的便利設計，不另外建立不同的平板帳務操作語意。
- Desktop／Tablet／Mobile 共用既有資料、CYID、角色權限、API、期初計算及存檔／失敗還原流程。

## 2. 目前介面基準

目前 `public/adaptive-ui.js` 的 viewport 分類為 Mobile <768px、Tablet 768–1023px、Desktop >=1024px。

電腦版左右工作區另由 `CY_V21_SPLIT_MEDIA = '(min-width: 1360px)'` 與 `.shell.v21-split-layout` 控制：左側 `.v21-entry-rail` 是記帳區，右側為看帳工作區；現有左欄 CSS 為 `minmax(380px, 420px)`，右欄使用剩餘空間。

因此「>=1024px 被分類為 desktop」不等於已啟用左右分欄。平板橫向不能直接照搬 1360px 門檻，也不能直接把桌面欄寬縮小而忽略觸控操作。

實作前需要再次核對當時 main 的配置與共用操作主路徑，避免以本文件中的歷史快照覆蓋後續修改。

## 3. 兩種方向的配置

| 項目 | 橫向 | 直向 |
| --- | --- | --- |
| 主結構 | 左側較窄記帳區、右側較大看帳區 | 上方大塊看帳區、底部記帳區 |
| 記帳呈現 | 常駐左欄，欄位在欄內分列排列 | 建議採可收合底部欄，展開後可固定 |
| 看帳呈現 | 表格，優先保留完整帳務資訊 | 依可用寬度調整表格與欄位呈現，保持金額與餘額易讀 |
| 捲動 | 看帳區獨立捲動；左欄維持穩定可操作 | 看帳區獨立捲動；記帳欄保留穩定位置 |
| 編輯 | 建議點選紀錄後帶入左側記帳區 | 建議點選紀錄後展開底部記帳欄並帶入 |
| 外接輸入 | 保留鍵盤、滑鼠及觸控 | 保留鍵盤、滑鼠及觸控 |

### 橫向尺寸提案

先以左欄約三分之一、右欄約三分之二作為設計起點，依實際欄位、表格和觸控可讀性調整；比例尚未定稿。

日期、帳戶、科目、摘要、金額及儲存按鈕放在左欄內，不排成跨整個畫面的上方記帳列。右欄包含月份切換、搜尋、月統計及帳務表格。

### 直向記帳欄提案

使用者提出的固定小區塊與收合欄方案，建議整合成以下三個狀態；預設狀態及最終高度仍待版面／實機驗收。

1. **收合**：只保留新增記帳、收入／支出及展開入口，將大部分空間留給看帳。
2. **展開**：完整記帳欄約占可用高度下方三分之一，欄位分兩至三列；提供固定展開選擇，方便連續輸入。
3. **鍵盤開啟**：依實際可視範圍調整，保持焦點欄位及儲存操作可達；看帳區暫時縮小，不能被記帳欄或鍵盤遮住最後一筆。

建議第一版直向預設收合，可固定展開；儲存後維持展開並標示新增紀錄。編輯時明確呈現「儲存修改／取消」，避免與新增混淆。

## 4. 手機觸控設計的共用與調整

| 能力 | 平板採用方向 | 平板需驗證的部分 |
| --- | --- | --- |
| 帳戶選擇 | 共用點擊展開 chooser／sheet 的選取方式 | 尺寸、位置、遮罩與鍵盤操作；橫向不直接搬成全螢幕手機頁 |
| 收入／支出 | 共用既有雙態切換、色彩語意及操作回饋 | 左欄與底部欄的尺寸及觸控命中範圍 |
| 日期／月份 | 共用現有自製 picker | 觸控、focus、外接鍵盤、彈出位置及可視範圍 |
| 科目／分類排序 | 共用觸控拖曳把手、插入提示、取消與邊緣自動捲動 | 手指拖曳與列表捲動不衝突；名稱區可正常捲動 |
| 帳戶排序 | 共用既有觸控排序與存檔／失敗回復流程 | 兩種方向均可操作，排序不覆蓋並行改名 |
| 交易操作 | 參考手機滑動編輯／刪除，同時保留可點擊入口 | 表格捲動與滑動操作不衝突；刪除沿用既有確認及權限 |
| 設定／彈窗 | 共用按鈕、選取狀態、共用設定 writer 與操作回饋 | 調整顯示空間，不照搬手機窄版尺寸 |
| 儲存／編輯回饋 | 共用 V0.22.1 的 optimistic、失敗還原及重複操作防護 | 新配置保持同一寫入主路徑與舊查詢回應保護 |
| Excel | 共用現有匯出服務及支援時的原生分享／下載 | 實際 iPad／Android 瀏覽器的交付方式 |

參考現有 `public/adaptive-ui.js`、`public/adaptive-ui.css`、`public/app.js`、`public/ledger-inline-edit.js`、`public/ledger-tools.js` 與相關 picker／settings 元件。共用手機的觸控元件與事件處理，但需拆除「僅手機寬度才能執行」的呈現限制，不能複製出第二套平板 writer。

## 5. 方向、空間與鍵盤處理

- 方向、可用寬度、觸控特性與視窗高度一起考量；不只依單一寬度推斷裝置，不新增平板登入 authority。
- 旋轉保留未儲存內容、目前月份、搜尋條件及選取紀錄；不得旋轉後自動送出、遺失草稿或誤變成新增。
- 螢幕鍵盤造成的可視高度變化，不應被誤判為使用者旋轉；登入、picker、焦點欄位與儲存按鈕均需實機確認。
- 不依賴 hover 才能發現或執行操作；觸控控件避免過小、過密。
- 分割視窗或可用空間不足時，保留安全可操作配置；具體切換條件待設計驗證，不先硬訂新的門檻。
- 外接鍵盤保留既有輸入導覽；滑鼠操作與觸控共用業務能力判斷。

## 6. 帳務與權限邊界

- 共用既有 `saveTransaction`、`persistTransactionUpdate`、設定 mutation 與 canonical API；方向只改 presentation。
- 期初及 Excel 使用同一計算；不新增平板專用期初算法或資料表。
- USER 維持只讀與 Excel 匯出；ADMIN／SUPER_ADMIN 沿用 server-side business gate。
- 人工期初、刪除、鎖帳、移轉、復原等沿用高風險確認及 server 成功後回饋。
- 登入仍走 CYID 與同一安全入口；平板登入可靠性納入驗收，不以新增 legacy auth patch 代替。
- 不因平板規劃修改正式帳務基準。移轉帳本內容已由使用者於 2026/10/03 確認 OK。

## 7. 建議實作與驗收順序

1. 核對當時正式基準、平板登入與現有手機觸控共用元件。
2. 先做橫向左右、直向上下／底部欄的版面草稿，確認欄寬、欄位與表格可讀性。
3. 接上既有記帳與編輯主路徑，再整合 chooser、picker、排序及交易操作。
4. 補旋轉、草稿、鍵盤、捲動與失敗還原測試。
5. 隔離環境驗證後，安排真實 iPad／Android 平板雙方向驗收；通過後依使用者授權部署。

| 驗收項目 | 通過條件 |
| --- | --- |
| 橫向結構 | 左記帳、右看帳，不誤套上下桌面配置；無不可達的操作 |
| 直向結構 | 看帳為主要空間；底部欄可收合、展開及固定 |
| 記帳／編輯 | 使用共用服務；新增、修改、取消、跨月及回復行為一致 |
| 旋轉 | 草稿、月份、搜尋、選取及編輯模式不遺失，不重複送出 |
| 螢幕鍵盤 | 焦點、輸入及儲存操作可達；關閉後版面恢復 |
| 觸控 | 選擇器、排序、滑動、點擊與捲動不互相攔截 |
| 失敗／延遲 | 背景寫入失敗能還原；舊查詢不能覆蓋已存檔新值 |
| 登入／權限 | 真實平板登入、Session、登出及 USER 唯讀通過 |
| 裝置回歸 | 手機既有流程與電腦左右配置保持可用 |

自動測試與模擬 viewport 只提供回歸證據，不能代替真實平板觸控、鍵盤、登入及視覺驗收。
