## 3. 折讓功能

### 3.1 暫行人工流程

在 AMEGO 折讓 API 正式串接前，先提供單純、可追蹤的人工處理流程；這是經使用者核准的暫時例外，目的在避免現在先做一套 API 整合、雲端化時又重做一次。

預定流程：

1. 從發票詳細資料按「折讓」。
2. 員工輸入折讓原因、員工編號與員工密碼。
3. 驗證員工存在、啟用且密碼正確；驗證失敗不得建立待處理事項。
4. 驗證成功後**不呼叫 AMEGO 折讓 API**，改在「上傳問題」建立一筆人工待辦。
5. 人工待辦類型使用「折讓人工處理」，並保存必要的發票識別、原申請員工編號、折讓原因與提出時間；不得保存員工密碼。
6. 管理員至光貿網站人工完成實際折讓。
7. 既有每日完整同步維持原流程；因官方 `invoice_list` 未提供足夠折讓資訊，僅針對仍處於「折讓人工處理」的發票，在每日同步時額外使用**既有 `invoice_query`** 單筆確認。`invoice_query` 若出現 `allowance[]`，即可判定光貿後台已有折讓資料。
8. 確認光貿已完成折讓後，更新本機可顯示的折讓狀態／資訊並自動結束對應人工待辦，避免永久留在「上傳問題」。

上述第 7 點是核准的暫時例外：只對仍待人工處理的折讓申請補查，不掃描所有發票、不建立另一套高頻同步，也不呼叫折讓專用 API。

暫行流程不做：

- 不由 CYInvoice 呼叫折讓開立／作廢折讓 API。
- 不在本機模擬光貿已完成折讓。
- 不自行產生官方折讓單號。
- 不建立另一套高頻率折讓同步排程；沿用每日完整同步，只對未結案人工折讓使用既有 `invoice_query` 補查。
