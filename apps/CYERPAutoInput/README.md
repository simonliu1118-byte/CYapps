# CYERPAutoInput

SMART ERP 自動輸入工具，以鼎新 SMART ERP `COPI08` 銷貨單建立作業為主要自動化目標。

## 版本

目前版本見 `VERSION`／`BUILD`（最新正式 Release 為 `V0.3.1`，tag `cyerp-auto-input-v0.3.1`）。C# 重寫線於 2026-10-11 由 PR #104 合併進 `main`、取代舊 Go 線。正式版從 GitHub Release 下載 `CYERPAutoInput_V0.3.1.zip`，解壓縮後執行 `CYERPAutoInput/CYERPAutoInput.exe`；開發中的測試包為 PR 的 CI Artifact。逐版變更見 `CHANGELOG.md`，目前狀態與待辦見 `WORK_HANDOFF.md`。

## 主要流程

```text
找到 COPI08（只允許一個）→ 最大化並帶到前景
-> 檢視狀態送 F5 新增；以交易資料「部門代號／業務人員」皆空白確認是新單
-> 輸入表頭 / 交易資料 / 送貨資料 / 發票資料（課稅別、發票聯數以下拉清單位置選取並讀回確認）
-> 點一次商品明細區建立第一列，以 PP-OCRv5 辨識明細欄位位置
-> 每列：品號 -> 單位（有指定才 F2）-> 數量 -> 贈/備品量 -> 庫別 -> 單價 -> 批號
         批號：按 F2，ERP 開出批號查詢才選由上往下第一筆「現有存量 > 0」；沒開出即視為無批號
-> 下鍵進入下一列；ERP「庫存量或批號量不足」提示按確定並記為待確認
-> 自動儲存（設定開啟時）：送 F12，確認回到檢視且單號相同；完成後列出待確認項目
-> 自動列印（設定開啟時）：Ribbon「列印」→「直接列印」
-> 已儲存就清空表單，準備下一張（待確認項目先列出）
```

## 介面

- 只送出有填內容的欄位；有資料的明細列必須同時有「品號＋數量」。
- 交易資料「付款條件」為標準欄位。ERP 依客戶自動帶出的付款條件、貨運別、送貨地址(一)、發票客戶全名、統一編號與表單不同時，以表單為準覆蓋（表單空白則保留 ERP 的值）；其他欄位 ERP 已有不同內容時停止，不覆蓋。
- 每次輸入文字前，本程式會把 ERP 該輸入框的中文輸入法切成英數，避免字停在輸入法組字區後跑到下一個欄位；備註、送貨地址(一)、發票客戶全名輸入後讀回比對，不符即停止。
- 日期欄位右側有日期選擇器；MO店+ 預覽的發票日期同樣可選日期，輸入時自動加「/」。
- 同一個 Windows 帳號只能開一個 ERP AutoInput；開第二個會提示已經開啟並結束。
- 工具列：開始輸入 ERP｜訂單匯入（蝦皮、MO店+、酷澎商城）｜ERP 狀態、設定、清除表單。按鈕比照 CYInvoice 放大（高 38、10.5pt），所有按鈕統一 2px 圓角（視覺規範 WinForms 參考值）。主畫面明細與匯入預覽的欄寬、列高固定。
- 輸入 ERP 期間（含放棄單據）忽略實體滑鼠（低階滑鼠攔截，只擋實體、不擋 本程式自己的點擊），避免移動滑鼠讓欄位跑掉；按 Esc 立即恢復滑鼠並緊急停止。
- 銷貨單別最多 4 字元；日期畫面顯示 `YYYY/MM/DD`，送 ERP 前正規化為 `YYYYMMDD` 並驗證為真實日期。單據日期可空白，ERP 會自動帶入今天。
- 課稅別、發票聯數為下拉選單，選項依 ERP 清單順序內建（標準分類，Governance 2.3.32 核准寫入 source）。
- 欄位區分三欄：表頭｜交易資料（上）與送貨資料（下）共用兩倍寬度｜發票資料；備註、送貨地址等長文字欄位佔整行。
- 商品明細預設 10 列，標準視窗剛好完整顯示、沒有捲軸；在最後一列輸入或按 Tab／Enter 離開最後一格時自動加一列，超過 10 列才出現垂直捲軸。欄寬與列高固定，不能拖曳調整。
- 明細有「運費品號」（設定）的列、而送貨資料・運費空白時，開始輸入前自動把該列金額（數量×單價）填入運費欄；運費欄已有值則不變。蝦皮、MO店+、手動輸入皆適用。
- 進階模式目前隱藏，固定使用標準模式（程式碼保留）。
- 蝦皮、MO店+、酷澎匯入：見下方「平台訂單匯入」。
- 右上角大標籤每秒顯示 ERP 狀態：`檢視`／`新增`／`修改`、`新增/修改？`（本程式開啟時 ERP 已在輸入中、無法判斷）、`多個 COPI08`（都不在檢視狀態）、`未開啟`（開始時會從作業速查開啟）、`無法判斷`。新增或修改的判斷依據：由檢視進入輸入的瞬間，部門代號與業務人員在新單必定空白、舊單必定有值。標籤只作提示，不阻止輸入。
- 狀態列提示 Windows 顯示比例：只以 100% 驗證，非 100% 時以警告色提示。
- 「清除表單」清空欄位與明細並重新帶入本機預設值；設定「儲存單據後自動清除表單」（預設開）：本程式儲存的單據在提醒視窗之後清空表單，單張、全自動與批次匯入都走同一段程式；未儲存不清空。MO店+／酷澎匯入按開始後若檢查不通過（資料不完整、重複單、ERP 輸入中選否），回到原本的匯入視窗，已填的發票資料保留；批次開始前會先檢查每一張。完成後若有待確認項目、未自動儲存或未自動列印會列出原因。

### 設定（只存本機 `Data/settings.json`）

分四頁：

- **一般**：
  - LOG 一律以診斷模式記錄實際內容（品號、單號、OCR 文字與位置），只存本機，方便排查（使用者 2026-10-11；設定已無此勾選）。
  - 自動儲存：預設關閉。只儲存 本程式自行新增的單據；開始時 ERP 已在輸入中且部門代號／業務人員已有值（可能是修改中的單據）則不儲存。有待確認項目的單據仍會儲存。
  - 自動儲存後按 ERP「列印 → 直接列印」：需先開自動儲存，預設關閉。儲存並確認回到檢視後，以 OCR 找 Ribbon 的「列印」點開選單（容許與相鄰文字黏在一起或第二個字讀錯；讀到的 Ribbon 文字都記在 LOG），只在讀到「直接列印」時點選；儲存後 ERP 可能還在處理，整段最多重試 20 秒；找不到時按 Esc 關閉選單並提醒，不影響已儲存的單據。
  - 全自動（V0.3.0，「蝦皮」按鈕選單：全自動／自動擷取輸入、匯入訂單匯出檔）：程式開一個自己的 Chrome 新視窗，對「我的銷售 › 待出貨 › 待處理」的訂單逐筆按「安排出貨」、列印寄件單、回訂單頁擷取、輸入 ERP、儲存並列印，直到沒有待處理訂單。先看「建議今天內出貨」，沒有就看「建議出貨期限：全部」。支援蝦皮店到店（含隔日到貨）、蝦皮店到宅、店到家宅配、7-11、全家、新竹物流（安排取件：取件地址必須與設定的「新竹取件地址」相同才按確認，否則取消並跳過）；寄件單印表機與各自的縮放（蝦皮 110%、7-11 100%、新竹 95%）在設定指定，每次列印前都重新設定並核對 Chrome 列印視窗；目的地不是設定的印表機時自動從「目的地」清單選回來。全家寄取貨單由程式存下原圖（暫存在程式同一層的 Temp 資料夾，用完刪除）、切出寄取貨單、以整數倍縮放成純黑白，直接送印表機印在 100×150 mm 標籤上（條碼線寬保持整數點，比較好掃）；切不出來或核對不到寄件編號時改用 Chrome 第 2 頁 165%。畫面以網頁原文讀取（讀不到才文字辨識）；「安排出貨」必須完整讀到、是橘色並與「不成立訂單」分開才會按。還沒有流程的物流（如萊爾富）、需要人工確認的訂單（例如庫存不足）記下來跳過，全部做完一次列出清單（顯示在最上層），並發出嗶聲、工作列圖示閃爍到切回程式為止（主機沒接喇叭時聽不到嗶聲：Windows 7 之後程式無法使用主機板蜂鳴器）；ERP 轉人工、未儲存或蝦皮端出錯則立即停止並說明停在哪一筆、蝦皮是否已安排出貨。執行期間畫面中央顯示「全自動運轉中」與計時，按 Esc 中止。買家備註出現「設定 › 發送訊息 › 蝦皮」裡某則的關鍵字時，安排出貨前先用聊聊送出那則訊息（符合多則就依序各送一次），再照常處理；送出的訂單列在結束清單。發送訊息可設多則，同一平台內一個關鍵字只能屬於一則；MO店+、酷澎區塊尚未開放。
  - 蝦皮自動擷取（一律開啟，2026-10-15 起設定不再有開關）：只限蝦皮自動擷取輸入（MO店+、酷澎要補發票資料，不適用）。按「開始」後擷取、判讀、帶回、輸入 ERP、儲存並列印（不論上面的自動儲存／列印設定）；擷取有問題改手動補圖後，按「帶入表單」一樣繼續；帶回時有待確認項目會先詢問，預設停止。全自動期間實體滑鼠全程鎖定，畫面中央顯示「全自動運轉中／按 Esc 中止」（不入鏡、不擋點擊）；需要使用者確認或中止時立即解除。一般按「開始輸入 ERP」（含批次）輸入期間同樣顯示「自動輸入中」。程式開著時在瀏覽器按 F8 即開啟蝦皮自動擷取輸入並開始擷取（只在瀏覽器在最前面時攔截 F8；一律開啟）。光學辨識的進度條依實際辨識的高度以百分比顯示。訂單編號前 6 碼與運送單號數字段的 O 視為 0、I 視為 1；帶入表單時商品依品號由小到大排列（折價券、運費、促銷組合排最後）；套裝貨號「A+B」（所有來源）拆成各品號，單價由 ERP 帶出原價並讀回，原價與套裝售價的差額併入促銷組合，售價高於原價合計時轉人工；訂單編號後 8 碼的 0／O 依截圖字寬判斷。
  - 商品明細第一列庫別預設填入：勾選並填庫別後，表單第一列庫別直接預填（啟動、儲存設定、清除表單時；已有值不覆蓋）；ERP 新增列會沿用上一列庫別。
- **平台匯入**：
  - 蝦皮：銷貨單別、客戶代號、備註前綴（預設「蝦皮訂單」）。
  - 酷澎：銷貨單別、客戶代號、備註前綴（預設「酷澎訂單」）。
  - MO店+：銷貨單別、客戶代號、備註前綴（預設「MO店+訂單」）、匯出檔密碼（以 Windows DPAPI 加密保存，只有同一台電腦同一個 Windows 帳號能解開；空白表示不變更）。
  - CYInvoice（在「一般」頁，MO店+／酷澎共用）：CYInvoice.exe 位置（只能按「選擇…」用檔案選擇器選）。設定 › 印表機另有熱感紙／A4 印表機勾選與紙本發票 PDF 格式（A4 整張、A4（地址＋A5）、A4（A5 內容）、A5、QRcode A4）。
  - 共用：折價券品號、運費品號、促銷組合品號（所有平台與手動輸入共用）。
- **貨運別**（所有平台共用）：分「物流」（郵局、大榮、新竹、黑貓、宅配通、嘉里，依 ERP 代號順序；「郵局」也比對「中華郵政」）、獨立的「本公司」與「超商」（7-11、全家、萊爾富、蝦皮店到店、蝦皮店到店 - 隔日到貨、店到家宅配）三區，各一格，只填 ERP 貨運別代號。匯出檔的物流商文字包含該名稱即套用（忽略空白；多個符合時取最長的名稱，例如「蝦皮店到店 - 隔日到貨」優先於「蝦皮店到店」）；物流商沒有設定代號時該訂單轉人工。蝦皮官方匯出檔目前沒有物流商欄位；日後出現 `shipping_carrier`、`shipping_option`、`寄送方式`、`物流方式` 或 `物流商` 欄位時自動套用。
- **本機預設值**：銷貨單別、部門代號等欄位的預設內容。

設定視窗按 Enter 移到同頁的下一個欄位，在該頁最後一個欄位（本機預設值為最後一列）按 Enter 才儲存。

## 平台訂單匯入

蝦皮、MO店+ 與酷澎共用同一套預覽、單筆輸入、批次輸入與防重複流程；差別只在讀檔與欄位對應。

### 預覽與輸入

- 匯入前先預覽：可匯入的訂單與無法匯入的列（原因列在下方）。有問題的訂單整張不匯入。每列前面有勾選框（按「輸入」欄標題全選／全不選），預設勾選可輸入的訂單；已由本程式儲存過的訂單顯示「已輸入過」、不能勾；需轉人工的訂單紅字、預設不勾，原因列在下方並可滑鼠停留查看。輸入結果不在預覽顯示，而是批次結束的結果清單。
- 「開始輸入」：勾一張時放到表單並直接開始輸入 ERP（單筆）；勾兩張以上為批次。
- 批次：需開啟自動儲存（未開啟時提示）；每張儲存後才接下一張。某張失敗時放棄 本程式為該張建立的 ERP 單據（先核對單號）後繼續下一張；需轉人工的訂單不進單，直接列為需人工處理。只有無法安全放棄或按 Esc 才停止。最後以共用的結果清單（全自動也用同一個，可捲動、可複製）列出已儲存、需回補物流單號、需人工確認、需人工處理、重複略過、失敗略過、停止原因與未處理的訂單。
- 轉人工的訂單：單筆輸入時只輸入到單頭（表頭與交易／送貨／發票資料）就停止，明細轉人工輸入並儲存；批次輸入時整張不進單，最後列為需人工處理。
- ERP 對統一編號跳出「統一編號輸入錯誤！」（例如非營利單位）時，本程式按確定後繼續；跳出其他訊息則停止。
- 統一編號 → 客戶全名：有統編而客戶全名空白時，自動查經濟部商工登記公示資料（先公司、再商號；免金鑰、需連外網），查到直接填入，可修改；查不到、離線或逾時就留空。適用手動輸入（輸入 8 碼統編時）、MO店+ 與酷澎預覽。每次都上網查、不在本機保存（避免公司改名後仍用舊名）。客戶全名不是必填：沒有時開始輸入前提醒一次，可以繼續送出（客戶全名留空）。
- 滿件贈送（設定 › 滿件贈送）：每張卡片設定品號（可多個，合計計算）、滿幾件、送幾件、送給件數最多的品號或指定品號，以及適用平台；匯入的訂單載入表單時，合計每滿幾件就在受贈品號第一列的「贈/備品量」填入送幾件（例如買 10 送 1：10 件填 1、20 件填 2）。
- 物流單號空白也可以輸入；單筆完成時與批次結果都會列出要回補送貨地址(一) 的訂單。
- 員工代號：程式開啟時詢問一次（可略過），本次開啟期間填入員工代號欄並優先於本機預設值，不存檔；狀態列「員工代號」可點選更改。這是暫時作法，之後接 CYID 時改為登入者對應的員工代號（TODO）。

### 防止重複打單

本機 `Data/order_ledger.json` 記錄 本程式輸入過的訂單（來源＋平台訂單編號），不提交、不放進下載包。

| 紀錄 | 單筆輸入 | 批次輸入 |
|---|---|---|
| 本程式已儲存 | 預覽顯示「已輸入過」、不能勾；從其他入口仍警告並擋下 | 同左 |
| 本程式輸入完成但未儲存（未開自動儲存） | 提醒，確認後可再輸入 | 開始前一次詢問：仍要輸入／略過這些／不開始 |
| 只輸入單頭就轉人工 | 同上 | 同上 |

紀錄讀不到（檔案損毀）時不匯入，避免在沒有防重複的情況下打單。

### 蝦皮自動擷取輸入

按「蝦皮」→「自動擷取輸入」。蝦皮後台的裝箱單沒有正確的明細金額，所以改用訂單頁截圖（使用者 2026-10-11）。先在瀏覽器開好訂單明細頁；截圖視窗開啟時自動擷取：本程式視窗暫時隱藏、忽略實體滑鼠，瀏覽器先按 Home 回到頁面最上方（點頁面左側空白處取得焦點），再一段段往下捲動截圖（捲動距離由畫面比對量出，不必調整瀏覽器縮放），讀到「買家總支付金額」或到底即停，依卡片標題切出訂單資訊、商品表、買家實付金額三段；Esc 停止。截圖視窗開啟後按「開始」（開啟「蝦皮自動擷取」時一打開就直接開始）；擷取與判讀都沒問題時自動帶回表單，有問題就提示並暫停。沒有完整讀到時會列出缺哪一段，可用「框選截圖」（拖曳框選、連續截圖、Esc 結束）、Ctrl+V 貼上或拖曳圖片檔補上。順序不限；每張以本機 OCR 辨識並自動判斷種類，卡片右上角的紅色 × 可移除該張：

- 訂單資訊：訂單編號、運送資訊（包裹的物流方式與 `#` 物流單號）。
- 明細（可多張，重疊的部分自動去重）：每個「商品選項貨號」為一項，取同一列的單價與數量；同一個編號下的多個商品（促銷組合）共用一個小計（上方為實際小計，下方劃線為原價）。表頭不在畫面內也能分欄。
- 買家實付金額：訂單金額、買家支付運費、各種優惠券、蝦幣折抵、買家總支付金額。

| COPI08 | 來源 |
|---|---|
| 銷貨單別、客戶代號、備註 | 設定「平台匯入・蝦皮」＋訂單編號 |
| 送貨地址(一) | 物流單號 |

| 運費 | 買家支付運費（大於 0 時） |
| 明細 | 商品選項貨號／數量／單價；套組貨號（`Y0033x2`、`Y0033*2`、`Y0033 x 2`）拆成品號、數量×n、單價÷n（除不盡時四捨五入到小數兩位，例如 119÷3＝39.67） |

- 蝦幣折抵不另打一列，只讓代收貨款變少（例如訂單 249、優惠券 −30、蝦幣 −53：明細 249＋折價券 −30，代收貨款 166）。
- 核對：明細小計合計＝訂單金額、各組單價×數量合計＝小計原價、訂單金額＋運費＋優惠＋蝦幣＝買家總支付金額、編號沒有缺號；不符時列出請人工核對。
- 一張訂單必須有訂單資訊、商品明細、買家實付金額三種截圖，缺少時按「帶入表單」會警告缺哪幾種，不帶入。
- 截圖方式與範例：截圖視窗右上角的「說明」（範例圖 `assets/help/*.png` 已將訂單編號、物流單號、商品選項貨號打馬賽克）。
- 不做批次：讀完帶入主畫面並列出要確認的項目（含防重複紀錄），補齊後由使用者按「開始輸入 ERP」。買家／賣家備註不在截圖中，請自行判斷。
- OCR 容錯（依實機 LOG 修正）：
  - 欄位依表頭位置判定；沒有表頭時以欄距與劃線原價判斷，漏讀數量不會把小計當成數量。
  - 單獨的「1」「2」常被讀成「一」「-」「乙」，視為數字；編號的猜測字形以同張讀得清楚的編號依序推算（由上往下連號）；漏讀的格子裁切後只用辨識模型重讀，信心低於 0.8 不採用。
  - 編號只認最左欄、表頭下方且與小計同高的數字；商品縮圖上的字（例如「5號杯」）不算。
  - 劃線原價漏讀或讀成比小計還小時，若商品合計大於顯示小計（折扣不超過一半），以合計當原價。
  - 數量仍讀不到時，單一商品的編號以小計÷單價推算並提醒核對；明細數字對不起來時不加促銷組合列。
- 截圖只在本機辨識，不保存、不上傳。

### MO店+ 發票（CYInvoice）

發票只由 CYInvoice 開立：CYInvoice 自己讀 MO店+ 未出貨匯出檔（用它自己設定的 MO 密碼，加密 `.xls` 需裝 Excel）、呼叫光貿、保存紀錄；本程式不持有光貿憑證，只負責呼叫、核對、帶入 ERP 與列印紙本。兩個程式在同一台電腦、同一個 Windows 帳號，不需登入；CYInvoice 開著時由它的主程式處理，沒開時以它最後**儲存**的環境（測試／正式）處理。

- 設定 › 一般 › CYInvoice：CYInvoice.exe 位置（只能按「選擇…」）；MO店+ 全自動一律開發票。設定 › 印表機：紙本發票 PDF 格式（A4 整張、A4（地址＋A5）、A4（A5 內容）、A5、QRcode A4）與 A4 印表機。
- 全自動（一律開發票）：配送中匯出後先查詢（同時得知 CYInvoice 是測試或正式環境），只對查無發票的訂單開立，不詢問；結果不明的再查一次，仍不明就轉人工，絕不重送開立。轉人工的訂單（店家備註等）不送 CYInvoice。每筆都核對發票號碼格式、日期、金額＝訂單開立發票金額、統編相同才帶入；其他留空並列出原因。
- 正式環境的發票才輸入 ERP；測試環境照常開立、帶入與列印，但不輸入 ERP。「MO店+ › 匯入訂單匯出檔」選訂單檔、開立前會問、停在預覽；按開始一律輸入 ERP，不論 CYInvoice 的環境（使用者自己切，環境顯示在開立前的詢問與預覽備註）。
- 紙本發票：紙本或載具由 CYInvoice 依開立入口決定（MO店+ 入口：一般消費者開會員載具不印，有統編抬頭開紙本要印；酷澎入口一律紙本，見下方酷澎）。光貿開立完成後才有 PDF，所以開立後在背景每 20 秒向 CYInvoice 要一次（最多 30 分鐘），不影響全自動與打單；拿到後在沒有輸入 ERP 的時候跳出放「A4 白紙」確認再印。印過的發票號碼記在 `Data\paper_invoices.json`（60 天），重跑不重印；取不到或按停止的會列出請在 CYInvoice 列印。
- 酷澎：CYInvoice 酷澎入口一律開紙本，每張都取 PDF；有統編依設定的版型，沒有統編一律 A4 整張且**雙面（長邊）**列印（A4 印表機必須支援雙面，否則列出請在 CYInvoice 列印）。CYInvoice 讀酷澎檔需要「訂單編號」「應開立予買家之發票金額」「顯示產品名稱」「數量」「訂購人姓名」「應開立予酷澎之發票金額」「統一編號」七欄。
- 每次呼叫的請求與結果留在 `Temp\invoice-日期時間\`，有問題時一起提供。

呼叫介面（CYInvoice PR #445 提供；程式在 `CyInvoiceLink.cs`、`MainForm.Invoice.cs`）：

```text
CYInvoice.exe --autoinput-query <request.json> --result <result.json>   只查詢，絕不開立
CYInvoice.exe --autoinput-issue <request.json> --result <result.json>   開立（已開過的回原發票）
CYInvoice.exe --autoinput-pdf   <request.json> --result <result.json>   只取官方 PDF，絕不開立
```

- request `cyinvoice-autoinput-request/1`：`requestId`（每次新的 GUID）、`source`（`mo`／`coupang`）、`file`（未出貨原始匯出檔的絕對路徑）、`orderIds`；pdf 另有 `pdfFolder`、`pdfStyle`（0／1／2／3／5）。結果檔每次用新路徑，不覆寫。
- result `cyinvoice-autoinput-result/1`：`environment`（`production`／`test`）與每筆 `orderId`（MO 原始訂單編號，測試環境也一樣）、`status`、`invoiceNumber`、`invoiceDate`（yyyy/MM/dd）、`buyerBan`（一般消費者空白）、`buyerName`、`totalAmount`、`message`，pdf 另有 `pdfFile`。
- status：`issued`／`existing` 核對後帶入；`failed`、`unknown` 轉人工；`skipped` 是查無發票（查詢時才拿去開立）；pdf 的 `ready` 再核對號碼與金額才印、`pending` 是光貿尚未完成。
- 結束碼 0 全部成功、1 部分待人工、2 請求或檔案有問題、3 目前無法安全處理；2／3 或逾時（每筆 60 秒＋60 秒）可能沒有結果檔，不可當作沒開，之後以查詢核對。

- 轉人工：公司商品代碼空白、組合品號、快遞公司沒有設定貨運別。
- 無法匯入：數量、銷售價格、買家發票金額或運費無法辨識；買家發票金額高於銷售價格合計加運費。

## 光學定位 / OCR

ERP 的明細表格、F2 查詢表格與 ERP 自繪訊息框的文字不在 Win32／MSAA 控制項中（早期以結構探測確認；探測功能已於 Build 30 移除），只能截圖辨識；表頭欄位、銷貨單號等一般欄位直接以 `WM_GETTEXT` 讀取。

- 引擎：本機 PaddleOCR PP-OCRv5 mobile（`ch_PP-OCRv5_det_mobile`、`ch_PP-OCRv5_rec_mobile`、`ch_PP-LCNet_x0_25_textline_ori_cls_mobile`）+ ONNX Runtime CPU，不依賴 Windows OCR 語言包。
- 比對前先做常見繁簡等價正規化（`数→數`、`库→庫`…）；容易誤讀的訊息只比對穩定片段。
- 新增／儲存使用 ERP 快捷鍵 F5／F12，不點 Ribbon；唯一點 Ribbon 的是選用的自動列印（OCR 找「列印」與「直接列印」，見設定）。頁籤沿用已驗證的 `TcxPageControl` 幾何位置。
- 商品明細：點一次 `TcxGridSite` 建立第一列後，以目前 Grid 幾何＋表頭 OCR 定位欄位；欄位不在可視範圍時以 ERP 原生左右鍵捲動後重新辨識，不使用固定螢幕座標。
- F2 單位：OCR 定位「換算單位」欄中的指定單位，點選後送 Enter，並確認查詢視窗關閉。
- F2 批號：等查詢畫面穩定且未被遮擋、讀到「批號／現有存量」表頭才判讀。「現有存量」逐格裁到字形後只跑辨識模型；ERP 的斜線 0 單獨出現時信心偏低，只有候選中沒有其他數字才接受。由上往下選第一筆可確認 `> 0` 的批號；在找到之前有任何一列無法確認就停止，不猜列。
- OCR 暫存 PNG 只存在 Windows Temp，辨識後立即刪除。
- 模型不提交到 repo。模型組（檔名、大小、SHA-256、Release tag、上游固定 revision）定義在 `tools/ocr-models.json`；`tools/fetch-ocr-models.ps1` 優先從本 repo 模型 Release 下載，失敗才用上游固定 revision，大小或 SHA-256 不符即中止。模型 Release 由 `CYERPAutoInput OCR Model Mirror` workflow 從 `main` 手動建立（不是產品版本），已存在的 tag 不覆寫。

## 安全設計

- 不對 SMART ERP 送出 `Ctrl+A`。
- 輸入期間忽略實體滑鼠；實體 Esc 由獨立執行緒偵測，即使主畫面忙碌也能立即恢復滑鼠。
- 自動操作期間全域 `Esc` 只中止 本程式後續動作，不替使用者按 ERP「取消」。
- 不自動操作 ERP「修改」。只有兩種情況會「放棄本次新增／修改」（點客戶代號欄 → Esc → 確認），且都會先核對狀態（PROJECT_RULES §1）：開始輸入時 ERP 已在新增／修改中、使用者在提醒視窗確認要放棄；批次中 本程式自己建立且失敗的單據。
- 不自行輸入銷貨單號；ERP 在單別／日期完成後產生，本程式讀取並驗證 `YYYYMMDDXXX`。單據識別為「銷貨單別＋銷貨單號」，例如 `T01-20260926001`。
- 開著多個 COPI08 時用最上層、在檢視狀態的那個，都不在檢視狀態才不開始；沒開 COPI08 時從 ERP 主視窗「作業速查」輸入 COPI08 自動開啟（ERP 縮到最小會先還原）。ERP 開著其他作業不影響，只有對話框會擋。行為與 CYERPAutoQuery 一致。
- ERP 各欄位與明細格（日期以外）用剪貼簿貼上（選取全部＋WM_PASTE），剪貼簿原內容在整張單結束後放回。
- 任何未預期視窗、焦點或欄位狀態都停止目前單據，不猜座標繼續；唯一自動處理的 ERP 訊息是「庫存量或批號量不足」（按確定並記為待確認，依使用者 2026-10-09 指示）。
- 下拉欄位、F2 單位／批號選取後都會讀回或確認視窗關閉，不以「看起來點到了」當作成功。
- LOG 一律記錄實際內容，僅供工程排查；只存本機 `logs/`，不提交 Git、不自動上傳，由使用者主動提供分析（PROJECT_RULES §3、§4；使用者 2026-10-11 確認）。
- 真實 ERP 代碼、客戶／品號／訂單／發票資料、runtime log 不得提交 Public source（課稅別、發票聯數的標準選項為核准例外）。

## 自動更新

V0.3.1 起，程式開啟約 20 秒後及每 4 小時檢查 GitHub 上本專案（tag `cyerp-auto-input-vX.Y.Z`）較新的正式 Release；草稿、預先發行與 Actions 測試包都不算。有較新版就自動下載 zip 與 `.sha256`，核對 SHA-256 後解壓到 `Temp\update-V版本`。沒有工作進行時（沒有自動輸入、全自動、紙本發票佇列或其他視窗）直接關閉程式、以背景 PowerShell 把新版檔案覆蓋到程式資料夾並重新開啟；正在工作時等空閒，或在程式關閉時替換（不自動重開）。`Data`、`Temp`、`logs` 不在下載包內，保持不變。測試包（`VX.Y.Z Build N`）只會更新到更高的 `X.Y.Z` 正式版。檢查或下載失敗只記 LOG，不影響使用。

## Build

需求：.NET 8 SDK；正式目標為 Windows x64 self-contained GUI。

```powershell
./tools/fetch-canonical-icon.ps1
./tools/fetch-ocr-models.ps1
dotnet test tests/CYERPAutoInput.Tests/CYERPAutoInput.Tests.csproj
dotnet restore CYERPAutoInput.csproj -r win-x64
dotnet publish CYERPAutoInput.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false
```

正式 Windows 編譯與驗收基準以 GitHub Actions Windows runner 為準。

`tests/CYERPAutoInput.Tests` 只測不依賴 Win32／WinForms／OCR 的純規則（日期、銷貨單號、庫存數字與低信心判讀、下拉選項比對、OCR 文字正規化、新增／修改判斷、蝦皮匯出檔與截圖解析、MO店+／酷澎匯入、貨運別比對、`.xls` 解密讀取、防重複紀錄、統編查名回應），以連結原始檔方式編譯，可在任何作業系統執行。光學流程由 `--vision-self-test` 驗證（含合成的「現有存量」儲存格）；CI 另以 `--ui-snapshot` 輸出主畫面、設定各頁、MO店+ 預覽、蝦皮截圖視窗與說明視窗 PNG 作為版面檢查 Artifact。蝦皮截圖解析的測試資料取自實機診斷 LOG 的 OCR 框位置，文字與代碼一律換成假資料。MO店+ 測試檔 `tests/CYERPAutoInput.Tests/Fixtures/mo_export_*.xls` 為假資料，由同目錄的 `make_mo_fixture.py` 產生，並以 msoffcrypto-tool＋xlrd 獨立驗證可解密。
