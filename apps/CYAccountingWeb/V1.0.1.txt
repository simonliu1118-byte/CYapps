CYAccountingWeb V1.0.1（Build 1）
日期：2026-10-31（台灣時間）
狀態：Build 1 修正月份選單裁切與視窗密度，待 PR 驗證、合併與部署。

Build 1 修正
- 同一功能返修依共通規則保留 V1.0.1、遞增 BUILD 至 1；使用者指定視窗寬度 400px。
- 原視窗 overflow:hidden 裁掉子層月份 popover，改為 overflow:visible；右側月份選單靠右對齊，結果區維持獨立捲動。
- 縮窄後結果改為同一表格三欄：日期／帳戶、科目／摘要、金額／查看，保留全部欄位，不使用固定六欄擠壓摘要。
- 預設年月發出既有 change lifecycle 同步選擇器標籤；表單同時消費 input／change，避免自訂月份只發 change 時沿用舊搜尋分頁。
- 不變更全帳簿搜尋 API、36 個月上限、權限、分頁及手機／平板。


功能
- 桌機搜尋列最右側新增「全帳簿搜尋」，開啟 400px 寬的小型對話框。
- 可輸入搜尋關鍵字並選起訖年月；前後端均限制最多 36 個月（包含起月與訖月），不可空白搜尋。
- 關鍵字比對摘要、科目、帳戶，包含歷史與封存帳戶；百分比與底線均為一般文字，不當作 SQL 萬用字元。
- 結果依日期及交易編號由新到舊排列，每頁 50 筆。下一頁依游標續查，已查看頁面的往返不重讀資料庫；沒有搜尋結果與請求失敗均有明確提示。
- 點「查看」沿既有月份載入與清單定位流程回到該筆；一般單月搜尋、分組、會計餘額與資料寫入不變。
- 手機及平板不顯示新入口，既有版面與功能保留。未新增部署、測試 Worker 或正式資料操作。

主責
- public/ledger-tools.js：既有搜尋列結構與動作 owner，並管理期間搜尋視窗的表單、分頁及結果；不增加第二個 #transactionRows renderer。
- src/index.js：在既有 transaction read owner 增加唯讀期間搜尋，使用既有 statisticsPeriod 年月邊界驗證。
- src/app.js：沿用 CYID、App Access、USER 唯讀與 recovery hold 檢查，不增加另一套授權。
- public/ledger-search.css：集中本功能樣式，不新增 observer、wrapper、retry bootstrap 或裝置專用資料流程。

讀取與額度
- 使用既有 idx_transactions_date 索引限定日期範圍，再以 (tx_date,id) 游標續查；每次回傳最多 50 筆、額外取 1 筆判定是否還有下一頁。
- 不做 COUNT、OFFSET、逐月／逐列查詢、不在開窗或每次輸入時自動查詢。
- LIMIT 是傳回筆數，並非 D1 掃描列數；稀疏關鍵字可能掃描該期間的交易。以每月 100–200 筆估算，36 個月候選約 3,600–7,200 筆；實際依帳本密度而定，另有原共用驗證查詢。此為估算，不是正式用量回讀。
- 本次開發正式 D1 讀取 0、寫入 0；全部測試使用合成記錄與記憶體 SQLite。主要三頁案例只執行 3 次搜尋 SELECT，未執行正式大量查詢。
