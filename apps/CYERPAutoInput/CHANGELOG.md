本檔保存可確認的歷史事實。目前所有版本皆為 PR #104 上的工程測試版，未正式 Release；`main` 仍是舊 Go 線 `V0.0.10 Build 19`。實機結果以 `WORK_HANDOFF.md` §4 為準。

## V0.2.0 — 2026/10/06 起（Claude Code 接手，工程測試中，未正式 Release）

- Build 25（2026/10/11）：蝦皮截圖明細：商品縮圖上的小字（例如「4號杯」）被 OCR 讀成單獨數字，誤當成編號，造成「第 4 項讀不到小計」。編號改為只認最左側那一欄（有表頭時以「編」的位置為準）。
- Build 24（2026/10/11）：蝦皮截圖明細：截圖沒拍到表頭又漏讀數量「1」時，原本把小計欄當成數量（單價 450 × 數量 450），促銷組合算成巨大負數。改為依表頭位置判定欄位，沒有表頭時以欄距與小計的劃線原價判斷右欄是小計，缺的數量格會裁切重讀；仍讀不到時，單一商品的編號以小計÷單價推算數量並提醒核對。明細數字（單價×數量 與 小計原價）對不起來時不加促銷組合列，改為提醒。
- Build 23（2026/10/11）：蝦皮截圖明細：實機 OCR 偵測漏掉單獨的「1」（編號與數量），造成「讀不到單價或數量」「缺第 1 項」；改為找出有單價卻沒有數量、有小計卻沒有編號的格子，裁切後只用辨識模型重讀。說明視窗的範例圖依視窗寬度縮放，不再有橫向捲軸。
- Build 22（2026/10/11）：蝦皮截圖輸入（OCR）：貼上訂單資訊、明細（可多張）、買家實付金額截圖，自動辨識種類並解析；優惠券合計為折價券、蝦幣只減代收貨款、運費品號＋運費欄、促銷組合品號＝Σ單價×數量−訂單金額、套組貨號拆數量與單價（小數兩位）；多項金額核對；讀完帶入主畫面由使用者確認後開始輸入。三種截圖缺一即警告不帶入；蝦皮按鈕旁加「?」說明（截圖方式與遮蔽後的範例圖）。設定共用加促銷組合品號。開程式時詢問員工代號（本次開啟期間使用，暫時作法，之後接 CYID）。
- Build 21（2026/10/11）：統一編號自動查客戶全名（經濟部商工登記公示資料 API：公司、再商號；每次上網查、不在本機保存，避免改名；查不到留空），手動輸入、MO店+、酷澎都適用；客戶全名改為不強制，沒有時開始前提醒、可繼續送出。設定視窗 Enter 移到下一欄，只有頁面最後一欄按 Enter 才儲存。貨運別依使用者代號順序排列，分「物流」與「超商」兩區。ERP 對統一編號跳出「統一編號輸入錯誤！」（非營利等，屬正常）時按 Enter（OK）繼續；其他訊息仍停止。
- Build 20（2026/10/11）：酷澎訂單匯入（DeliveryList .xlsx）：單價＝銷售價格、運費打運費品號並填運費欄、代收貨款＝買家發票金額合計、快遞公司依共用貨運別、寄件單號＝送貨地址(一)、統一編號有值時預覽必填客戶全名，預覽可填發票日期與號碼；應開立予酷澎之發票金額、配送訊息、捆綁配送不處理（使用者 2026-10-11）。目前只有單列範本，多品項格式待確認。
- Build 19（2026/10/11）：所有按鈕統一為視覺規範 WinForms 參考的 2px 圓角（Build 18 的 6px 太圓，使用者指定）；一般按鈕維持只換外觀的 owner-paint，與主要按鈕同一外觀。設定改為四頁（一般／平台匯入／貨運別／本機預設值）；折價券品號、運費品號、貨運別改為所有平台共用（舊的 MO店+ 設定自動搬移）；貨運別增加黑貓、宅配通、萊爾富、蝦皮店到店、蝦皮店到店 - 隔日到貨、店到家宅配（比對忽略空白、取最長名稱）；蝦皮匯出檔若有物流商欄位也套用貨運別。
- Build 18（2026/10/11）：所有日期欄位（主畫面單據日期／發票日期／指定日期、MO店+ 預覽發票日期）加日期選擇器；預覽的發票日期輸入時自動加「/」。修正表頭欄位被切到（群組建立後尺寸未再變動時沒有套用欄寬，改在載入、顯示與切換模式時統一套用）。所有按鈕改為 6px 圓角（使用者指定；視覺規範 WinForms 參考值約 2px，在使用者電腦上看起來是直角，比照 CYInvoice 6–7px），一般按鈕改為只換外觀的 owner-paint。匯入預覽欄寬與列高固定。設定的 MO店+ 貨運別改為固定三列（新竹／7-11／全家），只填 ERP 代號。修正貨運別沒有真的輸入：ERP 欄位畫面空白，Win32 讀到的卻是舊值「11」，CY 判定相同就跳過；改為讀到相同值也清除重打，貨運別離開後讀回比對。實機：Build 17 MO店+ 單筆輸入完成（備註中文、送貨地址、發票日期／號碼）。
- Build 17（2026/10/11）：根因：ERP 的中文輸入法開著時，CY 送出的字停在輸入法組字區（備註欄虛線底線），點到送貨地址(一) 時才被送進該欄，造成「目前已有內容」。改為每次輸入文字前把 ERP 輸入框的輸入法切成英數（跨程序 WM_IME_CONTROL）；備註、送貨地址(一)、發票客戶全名離開後讀回比對，不符即停止。
- Build 16（2026/10/11）：送貨地址(一) 列入「ERP 依客戶帶出、表單值覆蓋」欄位：Build 15 實測 ERP 該欄看起來空白，CY 卻讀到內容而停止（「目前已有內容」）；改為清除後輸入物流單號，並在診斷模式 LOG 記錄讀到的原內容與字元碼。實機：Build 15 工作列圖示正常。
- Build 15（2026/10/10）：介面重排：交易資料與送貨資料上下排列、共用兩倍寬度（備註、送貨地址佔整行）。商品明細欄寬與列高固定；預設 10 列完整顯示不出捲軸（不再有內建新增列，最後一列輸入或 Tab 離開時自動加一列）。工作列圖示：視窗建立後以 WM_SETICON 明確設定大小圖示（Build 14 實測工作列顯示通用圖示）。明細有運費品號而運費欄空白時，自動以該列金額填入運費欄。
- Build 14（2026/10/10）：MO店+ 訂單匯入：內建讀取有密碼保護的 `.xls`（RC4 CryptoAPI，不需要 Excel；密碼以 DPAPI 存本機設定）；一列一品項、同訂單多列合併，同品號同單價合併數量；折價券、運費各打一列設定的品號（單價＝−折價券金額／運費），運費另填運費欄，代收貨款＝開立發票金額加總，物流商依本機對照表填貨運別；運費與匯出檔運費欄位交叉核對，對不上不匯入；店家備註、品號空白、組合品號、物流商不在對照表時轉人工（批次略過）。預覽可填物流單號（可空白，最後列出待回補）、發票客戶全名（有統編時必填）、發票日期、發票號碼。蝦皮與 MO店+ 共用預覽與批次流程。防重複：本機記錄已輸入的平台訂單編號，CY 已儲存的單擋下（批次略過），未儲存或轉人工的單提醒。ERP 依客戶帶出的貨運別、發票客戶全名、統一編號與表單不同時改為覆蓋。交易資料「付款條件」改為標準欄位；ERP 依客戶自動帶出的值與表單不同時清除後輸入表單值，相同則略過。蝦皮批次遇到有買家／賣家備註的訂單不再進單，略過並在最後列為需人工處理；批次只在無法安全放棄或按 Esc 時停止。單筆輸入仍打完單頭後轉人工。
- Build 13（2026/10/10）：ERP「放棄本次新增／修改」：點客戶代號欄 → Esc → 確認視窗含「放棄」→ Enter → 確認回到檢視（CY 自己送出的 Esc 不會觸發緊急停止）。開始輸入（含蝦皮單筆／批次）前若 ERP 在新增／修改中，先詢問；確定後放棄該單據再從新增開始。蝦皮批次中某張失敗時，放棄 CY 為該張建立的單據（核對單號）後繼續下一張；無法安全放棄、按 Esc 或有備註轉人工時才停止。蝦皮預覽改為兩個主要按鈕：「開始輸入選取的訂單」（單筆直接打單）與「批次輸入」（未開自動儲存時停用並以提示說明），移除「載入到表單」。表單沒填單據日期時，改讀 ERP 自動帶入的日期來核對銷貨單號（原本直接停止）。
