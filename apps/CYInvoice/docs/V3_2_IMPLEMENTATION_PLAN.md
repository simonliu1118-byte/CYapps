## 2. 已定案的產品流程

### 2.1 共用入口：沿用「處理中」與「上傳問題」

沿用現有 RecordsControl 的「處理中」及「上傳問題」、InvoiceWorkQueue 與 SyncIssuesForm 的同一分類路徑；不再新增第三個等待清單、診斷中心或新的獨立待辦視窗。

| 入口 | 收納項目 | 行為 |
| --- | --- | --- |
| 處理中 | 等待主管、等待紙本、已送達但官方尚在處理／上傳、正常等待查證 | 顯示原因與最新狀態；需人處理的項目依角色可直接開啟詳情，程式等待的項目自動追蹤 |
| 上傳問題 | 明確失敗、逾時查證後仍無法確認、查無原發票、資料衝突、超限、保存失敗、權限／版本／設定異常 | 顯示具體原因、最後結果、下一步與「匯出問題診斷」，避免只有一句失敗或無效人工分類 |
| 已完成紀錄 | 官方可確認的開立／作廢及已完成處理 | 移出未完成清單，保留申請、核准、API 嘗試、官方結果與處置歷程 |

同一操作依目前狀態只出現在適當清單，不能因同時有歷史錯誤而重複顯示為兩筆待辦。故障恢復或官方完成後，解決原上傳問題並更新原操作，不另造新申請。

### 2.2 折讓開立：主管一次核准，程式連續完成

1. 員工沿原發票提出折讓，保留原因、含稅／未稅與品項、數量、負數折扣、七位固定小數、合法多次部分折讓及超額檢查。
2. 主管直接開啟該筆詳情：同畫面顯示原發票完整資訊、既有折讓、最新可折餘額、本次品項／金額、原因與申請人。不要求抄 ID、另開官方預覽或先按接手。
3. 主管確認並驗證當次權限後，按一次「核准並開立」。
4. 原業務 owner 連續完成最新官方狀態／餘額檢查、核准內容保存、配號、送出及查回。配號與狀態轉移是內部步驟，不另要求主管預留、重登入或點第二個送出按鈕。
5. 同一次操作維持畫面與選取，完成後自動更新清單。若最新資料使原核准內容失效，說明實際差異並讓主管重新確認；不得默默更改核准金額。
6. 官方受理但尚未上傳完成時放「處理中」自動追蹤；能可靠對應該申請的官方完成結果可完成業務，不再以缺少額外的本次 POST 歸因證明而永久維持 sending。外部既有同號仍不得直接冒認本次新折讓。
7. 原申請 ID、防連點／跨機並行修改、核准內容與每次 API 嘗試紀錄保留。同一次已成功或結果不明的 g0401 不因刷新、重開、換裝置而盲目再開一張；完成後不能把歷史送出鎖當成同原發票後續合法部分折讓的永久佔用鎖。

**佔號自動加號（使用者明確決定）：**收到光貿有效回覆 `4040161`／`4040162` 的明確佔號拒絕，就自動加一號再送，**不設換號次數上限**，不另要求主管覆核、文字確認、不同買方證明或人工預留。每次號碼／回覆與進度均記錄，畫面可見且可取消；中斷後先按原申請查明最後一次結果再接續，不能從第一號重跑。逾時／斷線、結果不明或其他錯誤不當成佔號，先查原號。無效／超出既有合法編號格式屬編號錯誤，不藉格式限制偷設換號次數上限。此為使用者指定的佔號處理，與故障自動重試分開，不套用人工設定的碰撞重試上限。

### 2.3 折讓作廢：完整資料、一次核准、立即執行

1. 員工指定原折讓及原因提出作廢。
2. 主管開啟原待辦，同畫面看到原發票完整資訊、原折讓完整資訊、作廢原因與申請人，確認後按一次「核准作廢」。
3. 程式即時確認主管權限、公司／環境及官方狀態，保存核准與操作紀錄，直接執行原號 g0501 並更新結果。
4. 移除「核准後保留15分鐘」、再次輸入「作廢 原號」、另按單次送出及跨 Local／Cloud 永久唯一送出交接門檻。保留一般權限、防連點、必要資料一致性與紀錄；核准不是可離線轉用的長效送出授權。
5. 原號已作廢時直接同步完成，紀錄可區分本次操作與先前已作廢，不要求證明一定由本次 POST 造成才結案；`4050132` 轉官方查證，`4050141` 等待官方處理。
6. 逾時先查同一原號；必要時允許同號有限次重試，而非永久禁止第二次 g0501。每次重試核對原操作、當前權限與官方狀態，不因重試建立新的作廢申請。次數／退避參數於實作前在同一計畫明列，不擴散成新平台。
7. 官方處理中列既有「處理中」並自動追蹤；仍無法確認、明確拒絕或本機保存異常才列「上傳問題」並附診斷。

光貿依據：[API 文件](https://invoice.amego.tw/api_doc/)、[API 錯誤代碼](https://invoice.amego.tw/info_detail?mid=71)。本計畫未宣稱供應商保證任意並行 g0501 都冪等；程式須辨識回覆與原號官方狀態。

### 2.4 離線、官方同步與歷史

- Local／CYID 角色、Workspace／Device、已知撤權不可降級放行與既有受保護離線規則保留；本次不授權擴大離線財務能力。Cloud 故障後 g0401 仍按原申請／原號確認，不把未知結果當佔號。
- 沿現有 invoice_list／allowance_list／invoice_query 與正常同步週期，重用同一流程內有效查證資料，移除因按鈕拆分造成的額外重查；送出前真正必要的狀態／餘額確認保留。
- 折讓對帳維持150筆折讓清單／50張原發票上限，涵蓋已知舊折讓輪巡；這不是整個程式所有光貿 API 的總預算。補清楚同日失敗停止／恢復策略，避免超限後每次排程從頭重跑；不得把此限制套到使用者指定無換號次數上限的佔號流程。
- **不得更改舊發票保留／清理。** 只有折讓對不上本機原發票時，才按原號查回；查無明確顯示「查無原發票」，不補造資料、不擴大掃描。原官方狀態變更歷程、PDF Cache 失效及獨立歷史保存沿用。

## 3. 上傳問題與診斷紀錄

### 3.1 共用診斷與匯出

- 每筆上傳問題都有可查證的診斷，沿原 application／work item／本機操作 ID 關聯，單次 API 嘗試附序號；不建立另一套業務狀態 owner。純正常等待保留申請／處理紀錄即可，不製造例外堆疊。
- 記錄版本／Build、時間與環境、Local／Cloud、操作與失敗階段、送出是否開始、回覆是否收到、HTTP／光貿錯誤碼、必要的去識別化請求／回覆欄位、查回結果及後續處置；無法判明的欄位標未知，不用「已開始」推定光貿已收到。
- Cloud 沿既有稽核／請求關聯補安全錯誤摘要，本機統一整理相關紀錄；無回覆亦保存本機已知請求關聯與狀態，供後續查證。不得為此另建遠端測試 handler、日誌平台或把完整交易明文搬到 D1。
- 「上傳問題」提供一個「匯出問題診斷」入口，一次輸出選取操作的歷程、相關錯誤及必要系統資訊；可帶回對話查明解法。基本版本資訊要能在資料庫／網路失敗時收集；日誌寫入失敗亦明確提示並提供可複製內容。
- 同一問題保留首錯、最新結果、發生次數與關鍵轉態，不只覆寫最後一句。佔號長流程每次記號碼／code／時間／進度，不重複整份發票；一般日誌輪替保護未解決問題的關鍵證據，解決後留下處置結果。
- 密碼、App Key、Token、簽章不得寫日誌；匯出預設遮罩買受人及敏感識別資料，保留一致關聯、必要格式／金額／差異。完整營運資料不進 Public Git／Issue／PR／Actions／Release，不自動送信或上傳。

| 問題 | 額外診斷證據 |
| --- | --- |
| 開票／折讓／作廢失敗或結果不明 | 原操作與各次嘗試、送出／回覆階段、錯誤碼、後續原號查回；區分官方處理與本機保存 |
| 查無原發票／資料衝突 | 查詢方式與範圍、官方回覆、預期與實際必要欄位差異 |
| 查詢超限 | 日期範圍、頁數、已讀筆數、上限、停止／恢復位置 |
| 本機保存失敗 | 保存步驟、例外類型與程式堆疊、光貿是否已受理／完成或仍未知 |
| Cloud／權限／版本／設定失敗 | 本機／雲端版本、請求關聯、拒絕階段、安全錯誤碼及必要 schema／功能狀態 |

### 3.2 移除獨立「系統診斷」

診斷匯出接好後，**同一實作批次**移除 SettingsForm 的系統診斷入口、SystemDiagnosticsForm、該視窗的重複連線查詢與純 UI smoke。版本、Windows／.NET、SQLite、WebView2、Excel、印表機等仍有用的資訊收斂到同一診斷收集 owner，按相關問題需要收集；不另維護兩套診斷。

## 5. 本機交回後的整合實作

以同一功能分支／PR 集中完成，不為每個按鈕、DTO或測試另開版本／工作單：

1. 核對本機完成報告與最新基準，界定已套 migration／現有資料；以現有 State／Mutation／Render／Lifecycle owner 延伸，不增加 wrapper 或第二套流程。
2. 串接 Local／CYID 折讓詳情→一次核准→查證／配號／送出；自動佔號加號、原號未知查回及正常官方結果收尾一起完成。
3. 串接折讓作廢詳情→一次核准立即執行／追蹤；移除期限／文字確認／永久單次作廢限制。必要 schema 變更以新 forward migration保留既有申請／核准／Claim／Audit歷史，舊未知紀錄須先查明，不直接假定可重送g0401。
4. 更新原 InvoiceWorkQueue 的「處理中／上傳問題」分流、角色操作與錯誤恢復；整合診斷、問題匯出及系統診斷退役。
5. 移除被取代程式／API／旗標與重複驗證，將測試改為驗證本計畫的現行 contract。維護用功能不要放到正常主管操作；真光貿驗收後才退役最後網站人工入口。
6. 完成本地必要驗證後集中提交，核精確 head CI；後續必要遠端 migration／Worker 啟用／真光貿另按具體授權與額度作業，最後獲正式 Release 授權。雙 Windows 真人驗收上線後補做。
