## 後續：發票同步與本機 SQLite（已定案方向，尚未實作）

本節屬未來規劃，**不得因整理已完成版本文件而刪除或誤標為 V2.3.0 現行功能**。V2.3.0 目前仍使用 JSON 本機資料。

- [ ] 將發票／明細的主要本機保存逐步遷移至 SQLite；遷移前先定義 schema、唯一鍵、既有 JSON 匯入／回退與損壞復原流程，不得直接覆寫現有資料。
- [ ] 程式啟動時同步一次；開啟期間每 5 分鐘同步一次；手動「重新整理」與前兩者共用同一套 **3 天範圍**同步流程，手動操作需有約 30～60 秒冷卻，避免連續重查。
- [ ] 每日另執行一次較完整同步，不以 3 天滾動範圍取代完整校對。
- [ ] 3 天同步以 `/json/invoice_list` 為主要來源，比對本機後，只對缺漏或狀態差異項目執行必要的 `invoice_query`／狀態更新；不得因同步直接重送發票。
- [ ] 使用者雙擊任一發票開啟詳細資料時，不論是否超過 3 天，一律再執行 `invoice_query` 確認該張最新狀態。
- [ ] 正式環境本機發票與明細保留 2 個發票期別；測試環境清單只查當天且本機測試資料預計只保留 1 天。清理前必須保證安全狀態與必要追蹤資料不會被誤刪。
- [ ] 「結果不明／同步失敗／尚待處理」保留專用處理視窗，可由使用者手動刪除或標記完成；任何自動同步都不得把不明狀態當成成功。
- [ ] 同步比對至少使用發票號碼、金額、買受人等必要欄位並能辨識作廢／重開差異；識別資料不得包含 App Key 或其他秘密。
