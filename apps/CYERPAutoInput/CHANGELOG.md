# CYERPAutoInput 版本紀錄

本檔保存可確認的歷史事實。目前所有版本皆為 PR #104 上的工程測試版，未正式 Release；`main` 仍是舊 Go 線 `V0.0.10 Build 19`。實機結果以 `WORK_HANDOFF.md` §4 為準。

## V0.2.0 — 2026/10/06 起（Claude Code 接手，工程測試中，未正式 Release）

- Build 14（2026/10/10）：MO店+ 訂單匯入：內建讀取有密碼保護的 `.xls`（RC4 CryptoAPI，不需要 Excel；密碼以 DPAPI 存本機設定）；一列一品項、同訂單多列合併，同品號同單價合併數量；折價券、運費各打一列設定的品號（單價＝−折價券金額／運費），運費另填運費欄，代收貨款＝開立發票金額加總，物流商依本機對照表填貨運別；運費與匯出檔運費欄位交叉核對，對不上不匯入；店家備註、品號空白、組合品號、物流商不在對照表時轉人工（批次略過）。預覽可填物流單號（可空白，最後列出待回補）、發票客戶全名（有統編時必填）、發票日期、發票號碼。蝦皮與 MO店+ 共用預覽與批次流程。防重複：本機記錄已輸入的平台訂單編號，CY 已儲存的單擋下（批次略過），未儲存或轉人工的單提醒。ERP 依客戶帶出的貨運別、發票客戶全名、統一編號與表單不同時改為覆蓋。交易資料「付款條件」改為標準欄位；ERP 依客戶自動帶出的值與表單不同時清除後輸入表單值，相同則略過。蝦皮批次遇到有買家／賣家備註的訂單不再進單，略過並在最後列為需人工處理；批次只在無法安全放棄或按 Esc 時停止。單筆輸入仍打完單頭後轉人工。
- Build 13（2026/10/10）：ERP「放棄本次新增／修改」：點客戶代號欄 → Esc → 確認視窗含「放棄」→ Enter → 確認回到檢視（CY 自己送出的 Esc 不會觸發緊急停止）。開始輸入（含蝦皮單筆／批次）前若 ERP 在新增／修改中，先詢問；確定後放棄該單據再從新增開始。蝦皮批次中某張失敗時，放棄 CY 為該張建立的單據（核對單號）後繼續下一張；無法安全放棄、按 Esc 或有備註轉人工時才停止。蝦皮預覽改為兩個主要按鈕：「開始輸入選取的訂單」（單筆直接打單）與「批次輸入」（未開自動儲存時停用並以提示說明），移除「載入到表單」。表單沒填單據日期時，改讀 ERP 自動帶入的日期來核對銷貨單號（原本直接停止）。
- Build 12（2026/10/10）：第二階段起步：蝦皮官方匯出檔匯入。按「蝦皮」選 .xlsx → 預覽訂單（可匯入／無法匯入及原因／備註）→ 載入單張到表單，或全部依序輸入 ERP（需開啟自動儲存，每張儲存後接下一張，任何失敗即停止並列出已儲存／停止原因／未處理）。對應：銷貨單別、客戶代號、備註前綴由本機設定提供（真實代碼不寫入 source）；備註＝前綴＋order_sn；送貨地址(一)＝tracking_number；明細由 product_info 的商品選項貨號／數量／價格帶入品號／數量／單價。有買家備註或賣家備註的訂單只打完單頭就停止轉人工（不輸入明細、不儲存），批次停在該張。送貨地址(一) 改為標準模式欄位。內建 .xlsx 讀取（無第三方套件）。實機：Build 11 換列庫存不足提示按確定後繼續打完並列出待確認（第一階段完成）。
- Build 11（2026/10/10）：換列時的庫存不足提示按確定後，改為只檢查「下一列」的序號格有沒有字來判斷 ERP 是否已建立該列（未建立的列序號格空白）。原本整欄 OCR 讀序號，新列是藍底選取列加上斜線 0 而漏讀，誤判為未換列而停止。實機：狀態標籤「修改」顯示正確；單列單據 F12 時的庫存不足提示按確定後完成儲存並列出待確認。
- Build 10（2026/10/09）：課稅別、發票聯數改為下拉選單，選項依 ERP 清單順序內建（Governance 2.3.32 核准）。ERP 端打開下拉後按上鍵到頂、再按下鍵到該選項位置後 Enter，讀回 ERP 顯示值核對代碼，不符即停止。進階模式先隱藏（程式碼保留）。修正切回標準模式後欄位群組殘留橫向捲軸。實機：兩欄選取正確。
- Build 9（2026/10/09）：F12 儲存時出現的「庫存量或批號量不足」提示同樣按確定、記為需人工確認；ERP 仍在輸入狀態則再按一次 F12（最多處理 2 次）。設定視窗加高，避免下緣按鈕被切到。
- Build 8（2026/10/09）：換列時的「庫存量或批號量不足」提示（ERP 自繪訊息框，OCR 會把「庫」「號」讀錯）改以「存量／批／不足」片段辨識，按確定後讀明細「序號」欄確認已建立下一列，否則再按一次下鍵；有警告的單仍自動儲存，完成後列出待確認項目。
- Build 7（2026/10/08）：F2 批號查詢只在畫面穩定（連拍兩張相同）、未被遮擋、「批號／現有存量」表頭都讀到且無「換算／單位」字樣時才判讀，最多重試 4 次。原因：查詢視窗尚未繪製就擷取，讀到後方 COPI08 明細的「單位」。實機：批號選取成功。
- Build 6（2026/10/08）：設定「商品明細第一列庫別預設填入」改為直接預填到表單第一列，由 CY 輸入 ERP（ERP 新增列會沿用上一列庫別）。
- Build 5（2026/10/08）：新增上述設定（第一版只在開始輸入時帶入，Build 6 修正）。
- Build 4（2026/10/08）：F2「現有存量」改為依字色正規化；ERP 的斜線 0 單獨出現時信心偏低，只有候選中沒有其他數字才接受（`TryAcceptLowConfidenceStock`）。
- Build 3（2026/10/08）：是否需要批號改以 ERP 的 F2 反應為準（2 秒內無查詢視窗即無批號），原因是目前列每格的「…」按鈕被誤判為批號標記。批號表頭放寬比對並記錄 `F2_BATCH_TOKEN`。
- Build 2（2026/10/08）：新增改送 F5、自動儲存改送 F12（Ribbon「儲存」群組內含「取消」，點擊會誤按）。新增／修改改以交易資料「部門代號／業務人員」是否空白判斷。ERP 訊息框沿用 COPI08 標題，不再誤判為「多個 COPI08」。F2「現有存量」單格改為裁到字形後只跑辨識模型（`RecognizeLineAsync`）。
- Build 1（2026/10/06）：設定視窗「ERP 結構探測」（唯讀、有界，輸出 Win32／MSAA 控制項樹到本機 LOG）。
- Build 0（2026/10/06）：使用者指定升 Minor，代表 Claude Code 接手。含原 V0.1.0 Build 26／27：ERP 單據狀態大標籤、多個 COPI08 時不開始、顯示比例提示、診斷模式、銷貨單號以 `WM_GETTEXT` 讀取、純規則單元測試、選用自動儲存、清除表單與開啟 LOG、依 CY 視覺準則整理介面、CI 介面截圖、OCR 模型以 SHA-256 鎖定。
