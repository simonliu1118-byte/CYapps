# CYInvoice 待辦與驗證

本檔只保留**目前仍未完成、需要後續驗證或尚未取得足夠樣本**的工作。已完成內容與歷史決策應由 `CHANGELOG.md`、`MIGRATION_HISTORY.md`、PR 與設計文件保存，不在 TODO 重複堆疊。

目前工程開發基準：**CYInvoice V2.6.2**  
最新正式 Release：`cyinvoice-v2.4.2`

## 1. V2.5／V2.6 實機與光貿驗證

V2.5 員工帳戶、權限與作廢流程，以及 V2.6 暫行人工折讓、pending 追蹤、超過兩期管理員結案，均已完成工程實作與 Windows CI。以下仍需真實環境／人工操作驗證：

- [ ] 使用者實機回歸 V2.5／V2.6 新視窗、員工作廢、紙本未收回人工確認、人工折讓與「上傳問題」操作。
- [ ] 測試環境實際送出直接作廢 `3015-消退` 與管理員覆核作廢 `3001-3015-消退`，保留完整 `invoice_query` JSON，確認 AMEGO 是否會回傳可解析的 `CancelReason`／作廢原因；官方文件目前只明確保證 `cancel_date`，不得假設未文件化欄位一定存在。
- [ ] 測試環境實際建立一筆人工折讓後，以 `invoice_query.allowance[]` 驗證同日舊／新折讓的辨識結果與金額比對。
- [ ] V2.6.2 實機驗證 `/json/allowance_file` 三種官方版型 (A4、A4 地址+A5、A5) 均能下載、進入既有 WebViewer 並正常列印。
- [ ] V2.6.2 實機驗證「折讓作廢」暫行人工流程：一般使用者可提出申請，管理員可在「上傳問題」查看、標記已解決或取消退回，現階段不得直接呼叫 `/json/g0501`。
- [ ] 實機確認超過兩期的作廢／折讓 pending 顯示「可結案」，只有 ADMIN／SUPER_ADMIN 可結案；結案後停止本機追蹤並恢復一般 retention 清理資格。

正式 Release 仍只在使用者於當次工作明確要求發布時執行；VERSION／BUILD、PR merge、工程測試包都不等於 Release 授權。

## 2. V2.4.x／既有同步與 Cache 實機回歸

V2.4.2 已正式 Release。下列項目若沒有另外留下可追溯的實機驗證紀錄，後續維護時仍保留為回歸清單；**不要因已發布就反推為一定完成**。

- [ ] 以 V2.3.0 真實 `Data` 備份升級到現行 SQLite，確認 DB 建立、舊 JSON 保留、資料筆數與內容一致。
- [ ] 正式環境手動 recent 3-day sync，確認可抓到另一台電腦／光貿端的合法更新。
- [ ] 程式持續開啟超過 5 分鐘，確認啟動同步／每 5 分鐘同步不重疊，手動重新整理維持 30 秒冷卻。
- [ ] 確認每日第一次同步會執行完整兩期校對，而且不影響啟動／5 分鐘／手動共用的 recent 3-day 核心。
- [ ] 雙擊不同日期的發票，確認每張都先 `invoice_query` 再顯示詳細資訊；query 無法確認時不得把舊 Cache 冒充最新資料。
- [ ] 「上傳問題」視窗確認帳號隔離、一般 sync issue 標記已解決、作廢／折讓 pending 不可被一般按鈕繞過、Failed 紀錄刪除與重新整理流程。
- [ ] 測試環境 namespaced OrderID 實機確認：不與共享測試池其他資料撞號，UI 顯示仍維持原始可讀 OrderID。
- [ ] 紙本 PDF／預覽 Cache 實機確認：Cache 下載後內容，不保存短效 `file_url`；過期資料清理時同步移除對應 Cache。

## 3. 酷澎樣本補齊

目前已完成已寄出 DeliveryList 的基本解析與開票流程；以下格式仍缺可靠實際樣本。沒有樣本前維持安全停止，不猜欄位／金額。

- [ ] 未出貨／不同狀態的實際樣本。
- [ ] 公司統編訂單樣本。
- [ ] 多商品訂單樣本。
- [ ] 數量大於 1 的樣本。
- [ ] 折扣／負數調整樣本。
- [ ] 取得樣本後補 parser／金額／防重與測試案例。

## 4. 正式折讓 API（雲端化階段）

目前 V2.6.2 仍以人工折讓／人工折讓作廢待辦為主；完成紀錄繼續以 `invoice_query.allowance[]` 為官方依據。正式 AMEGO 折讓開立與作廢 API 整合延後到 CYInvoice 整體雲端化階段，再以正式資料模型一次完成。

- [ ] `/json/g0401` 折讓開立：由 CYInvoice 直接送出，不再要求管理員到光貿網站人工建立。
- [ ] `/json/g0501` 折讓作廢：正式自動化後改為只有 ADMIN／SUPER_ADMIN 可直接執行；送出前需重新查詢折讓最新狀態、再次確認，結果不明時不得自行標成成功，必須進「上傳問題」等待確認。
- [ ] `AllowanceNumber` 由 CYInvoice 自動產生；建立唯一編號規則與跨裝置／雲端防重機制。
- [ ] `allowance_query`／`allowance_status` 正式查詢與狀態同步。
- [ ] 折讓 PDF 已於 V2.6.2 使用 `/json/allowance_file`；雲端化時確認 Cache、權限與多裝置行為，不另造第二套 PDF 流程。
- [ ] 折讓清單與正式本機／雲端資料模型。
- [ ] 部分折讓、多次折讓、品項／數量／金額規則。
- [ ] 發票與折讓間的防重、timeout、結果不明與同步安全規則。
- [ ] 自動折讓 API 實作時，確認 AMEGO 正式可保存且可由折讓單號查回的欄位，將 `管理員編號-使用者編號-原因` 寫入該官方資料；之後以折讓單號重新查詢並解析操作人與原因。若 API 沒有適合的官方欄位，不得自行假設或濫用未文件化欄位，需另行定案。
- [ ] 雲端化完成後移除暫行人工折讓與人工折讓作廢方式，收斂為正式 API 流程。
