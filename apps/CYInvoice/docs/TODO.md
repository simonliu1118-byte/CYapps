# CYInvoice 待辦與驗證

本檔只保留**目前仍未完成、需要後續驗證或尚未取得足夠樣本**的工作。已完成內容與歷史決策應由 `CHANGELOG.md`、`MIGRATION_HISTORY.md`、PR 與設計文件保存，不在 TODO 重複堆疊。

目前工程開發基準：**CYInvoice V2.6.1 Build 2**  
最新正式 Release：`cyinvoice-v2.4.2`

## 1. V2.5／V2.6 實機與光貿驗證

V2.5 員工帳戶、權限與作廢流程，以及 V2.6 暫行人工折讓、pending 追蹤、超過兩期管理員結案，均已完成工程實作與 Windows CI。以下仍需真實環境／人工操作驗證：

- [ ] 使用者實機回歸 V2.5／V2.6 新視窗、員工作廢、紙本未收回人工確認、人工折讓與「上傳問題」操作。
- [ ] 測試環境實際送出直接作廢 `3015-消退` 與管理員覆核作廢 `3001-3015-消退`，保留完整 `invoice_query` JSON，確認 AMEGO 是否會回傳可解析的 `CancelReason`／作廢原因；官方文件目前只明確保證 `cancel_date`，不得假設未文件化欄位一定存在。
- [ ] 測試環境實際建立一筆人工折讓後，以 `invoice_query.allowance[]` 驗證同日舊／新折讓的辨識結果與金額比對。
- [ ] 實機確認超過兩期的作廢／折讓 pending 顯示「可結案」，只有 ADMIN／SUPER_ADMIN 可結案；結案後停止本機追蹤並恢復一般 retention 清理資格。

正式 Release 仍只在使用者於當次工作明確要求發布時執行；VERSION／BUILD、PR merge、工程測試包都不等於 Release 授權。

V2.4.2 已正式 Release。下列項目若沒有另外留下可追溯的實機驗證紀錄，後續維護時仍保留為回歸清單；**不要因已發布就反推為一定完成**。

- [ ] 正式環境手動 recent 3-day sync，確認可抓到另一台電腦／光貿端的合法更新。

## 3. 酷澎樣本補齊

目前已完成已寄出 DeliveryList 的基本解析與開票流程；以下格式仍缺可靠實際樣本。沒有樣本前維持安全停止，不猜欄位／金額。
