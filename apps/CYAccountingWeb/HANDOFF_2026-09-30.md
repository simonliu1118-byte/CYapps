## 4. Login/startup incident — resolved

The production login/startup incident is resolved on **V0.21.7 Build 5** and has real-mobile acceptance.

Root cause:

- the semanticized frontend still contained historical patch-era version writers;
- an old version MutationObserver forced the visible version to one historical value while a current-version MutationObserver forced the same DOM node back to the current value;
- this created MutationObserver ping-pong and could starve the browser event loop, which made timers, fetch timeout handling and navigation appear to hang;
- a desktop migration module also retained an independent historical version write.

Resolution:

- remove all frontend JS ownership of the global version display;
- keep `index.html` as the sole visible version source;
- retain hard bounds around CYID Service Binding, browser Session/API fetches and protected static assets;
- keep login success gated on a valid CYID Session resolve;
- CI now prevents frontend version mutators from returning.

Do not reopen this incident by adding a new auth/version wrapper. If a future startup issue appears, diagnose the current functional path directly.
