# CYInvoice C# 重製線

## 定位

- 版本以 `V1.1.0-cs.N` 標示。
- 這是 C#／WinForms 重製測試線，並非 Go `V1.1.0` 的後續正式版本。
- Go `V1.1.0` 的 commit、tag、Release 與原始碼保持不動，若重製失敗可直接回復。
- C# 重製在功能、安全規則與實機操作通過前，不得取代公司使用的 Go 正式版。

## 第一階段範圍

只重製 Go `V1.1.0` 已有能力：光貿 API、手動開立、ERP／MO店+／酷澎匯入、設定、本機紀錄、查詢與唯讀明細。

PDF 預覽、作廢與折讓不進入第一階段。完成同等功能與實機驗收後，才進入 `1.2.0` 功能開發。

## 不可改變的安全規則

- 結果不明、處理中及未知狀態一律禁止重送。
- `OrderID` 不可單獨視為成功；必須核對發票號碼、金額、稅額、總額、明細稅別及作廢狀態。
- 測試／正式環境資料與防重判斷隔離；舊紀錄採較安全的跨環境阻擋。
- 遠端已成功但本機保存失敗，仍須呈現「已開立」與本機保存錯誤，不可改標失敗。
- API、Excel、檔案 I/O 不在 UI thread 執行；只有 UI thread 能操作 WinForms control。
- 金額核心使用固定 7 位小數，不使用 binary floating point 作為發票計算依據。
- 設定與發票 JSON 損壞時停止並保留原檔；不得自動覆寫。
- App Key 與 MO店+ 密碼使用 Windows DPAPI；不得明碼落盤或寫入 Log。

## 目錄

- `src/CYInvoice.Core`：計算、模型、API、儲存與匯入等非 UI 邏輯。
- `src/CYInvoice.WinForms`：Windows Forms UI；僅協調 UI 狀態與背景工作。
- `tests/CYInvoice.Core.Tests`：不依賴外部 test framework 的 parity test runner，CI 直接執行。

## 目前狀態

`V1.1.0-cs.4` 是同一輪 Windows 實機驗收返修，不另消耗 `cs.N`。主頁改用原生 WinForms `TabControl`；商品與已開立清單改用原生 `ListView`，表頭不可點按或拖動，右側永久保留 Windows themed 垂直 scrollbar 槽，資料溢出時由同一位置的 ListView scrollbar 接手，欄寬總和不產生水平 scrollbar。商品區固定顯示表頭加五列，只有第一列是實際資料；品名、數量與單價以單擊開啟的暫時原生 TextBox 編輯並全選，Enter／Tab 依品名、數量、單價移動，金額維持唯讀灰底，刪除顯示為標準按鈕外觀。已開立清單使用 9pt 字級、整頁斑馬紋空白列，實際資料列雙擊仍開啟唯讀明細。

Run #10 後的同一輪返修把主畫面提高為 12pt、環境標題提高為 14pt，已開立清單維持 9pt；正常狀態固定使用預設尺寸，只保留最大化、還原與最小化，不允許任意拉伸。兩張 ListView 表頭與表身改用同一組欄界線繪製，並把停用或啟用 scrollbar 槽納入欄寬，避免最右欄被切除。商品區依 Windows 實際 header 與 row 高度固定為五列，暫時 TextBox 在清除 ListView 選取後才取得焦點，避免單擊後游標立即消失。主視窗亦明確從 EXE 內嵌資源載入 Icon，供標題列與工作列使用。

首次設定視窗的 Tab 與 Enter 都依 MO店+ 密碼、管理密碼、確認密碼前進，最後一欄 Enter 直接完成；欄位驗證失敗會回到對應欄位。MO店+ Excel COM 反射錯誤會展開到實際內層原因並寫入本機 `Logs/import-error.log`。酷澎匯入支援 `.xls`、`.xlsx`、`.xlsm`；Open XML 格式由不執行巨集的受限讀取器解析，舊式 `.xls` 才透過安全設定的 Excel COM 唯讀讀取。

同一返修亦恢復訂單編號與買方資料各自獨立的二選一群組；一般消費者鎖定統編與買方名稱，公司統編才啟用並由既有驗證要求兩欄必填。日期範圍使用固定「至」分隔。設定頁在測試環境停用正式統編與 App Key，既有 App Key 與 MO店+ 密碼的保留說明改放進欄位 placeholder。全新安裝改用不可略過的首次安全設定視窗，直接收集 MO店+ Excel 保護密碼及兩次管理密碼，首次環境固定為光貿測試；取消設定即關閉主程式。這些變更只涉及 C# preview UI 與啟動流程，未改動發票成功判定、防重、環境隔離或 Go 正式線。

`V1.1.0-cs.4` 先前已修正 `cs.3` 建立商品空白顯示列時，對尚未加入 DataGridView row 的操作儲存格過早設定 `ReadOnly`，導致主視窗建構立即中止的問題。程式入口保留啟動錯誤提示與本機 `Logs/startup-error.log`，Windows CI 保留 WinForms 主視窗建構 smoke test，避免再交付雙擊後無畫面的版本。

`V1.1.0-cs.3` 延續已建立的 C# 核心與 WinForms 主介面，修正第一輪 Windows 實機驗收發現的頁籤、設定按鈕、Radio 分組、商品列與清單斑馬紋問題。商品表預設只有一筆實際資料，另外四列為不可選取且不參與開票的 UI 空白列；新增明細後才建立新的實際資料列。數量與單價編輯時會全選既有內容，Enter 依品名、數量、單價及下一筆品名移動，唯讀金額欄不進入操作順序。

`V1.1.0-cs.2` 已建立 C# 核心與可操作的 WinForms 主介面、光貿簽章／查詢 client，以及與 Go JSON 相容的設定、發票紀錄及買方名稱儲存層。設定使用相同 PBKDF2 參數，Windows 執行端使用 DPAPI；JSON 採同目錄暫存檔、flush-to-disk 與 `MoveFileExW` write-through 取代。

手動開立的安全狀態機已依 Go 正式版移植：送出前先保存處理中紀錄、明確 API 拒絕與不明結果分流、Order ID／發票號碼／金額／稅額／DetailVat 嚴格回查、結果不明防重、作廢後以新 API Order ID 重開，以及遠端成功與本機保存失敗分離。負數折扣列、固定 7 位小數與含／未稅計算亦有 parity tests。

MO店+與酷澎原始匯出檔的轉換核心已移植。使用者只選擇平台原始檔：MO店+讀取原始 `OrderExport`，程式在背景 STA 執行緒透過已安裝的 Excel 解密，開檔前強制停用巨集、事件及外部連結；酷澎原始 `.xlsx`／`.xlsm` 以受限 Open XML 讀取器在背景執行，舊式 `.xls` 透過相同安全設定的 Excel COM 唯讀讀取。兩者都只在記憶體內轉成光貿開票所需的標準資料，再進入相同的固定小數與發票安全驗證。光貿官方轉換後範例只作為欄位映射及結果比對依據，不是日常輸入檔。

手動開立、設定、發票清單、唯讀明細，以及 MO店+／酷澎共用的匯入確認視窗已接入。匯入確認會顯示逐張統編查詢與開立狀態，只有勾選且完成資料核對的訂單才按順序送出；結果不明與遠端成功但本機保存失敗均保留並禁止重送。

鼎新 ERP 仍缺實際銷貨單樣本與欄位對照，因此只保留明確安全停止，不會猜測內容或送出發票。C# preview 尚未完成 Windows 實機驗收，不得視為 Go 正式版的替代品。
