# CYInvoice Windows 候選版驗證清單

本清單等使用者方便時再一次執行。所有開票測試先使用光貿測試環境；尚未完成整批驗證前，不切換正式公司環境。

## A. 全新啟動與安全設定

1. 將候選版解壓縮到全新資料夾，確認原本沒有 `Data/settings.json`。
2. 啟動 `CYInvoice.exe`，應強制顯示「首次安全設定」。
3. 按視窗關閉鍵，程式應拒絕略過並保持在設定畫面。
4. 管理密碼或 MO店+ Excel 密碼任一留白，應拒絕儲存。
5. 輸入兩組測試用密碼並完成，才可進入主畫面；環境應為光貿測試。
   - 視窗與輸入框應為精簡尺寸，所有說明及欄位文字背景透明；字級小於主介面，MO店+ Excel 密碼標籤不得破行。管理密碼 Enter 到 MO店+ Excel 密碼，在 MO店+ Excel 密碼再按 Enter 應直接完成設定。
6. 關閉後重新啟動，首次設定視窗不應再次出現。
7. 打開 `Data/settings.json` 檢視，兩組密碼不得以明文出現。

## B. 手動開立

1. 使用自動訂單編號開立一張一般消費者測試發票。
   - 光貿收到的 BuyerIdentifier 應為 `0000000000`，BuyerName 應為「消費者」。
2. 加入兩筆以上商品，確認預覽的品名、數量、含稅單價與總額一致。
   - 商品明細應是有原生表頭、格線與捲軸的真正表格，不得再看到長條輸入框疊在整列上。
   - 點品名、數量或單價格才出現該格編輯框；第一次取得焦點時原內容立即全選；品名 Enter 到數量、數量 Enter 到單價。單價編輯框內維持純數字，按 Enter、Tab 或離開儲存格後才顯示千分位。
   - 含稅／未稅應顯示圓點選項，選中的選項有淡藍高亮；一般消費者固定含稅。
3. 使用合法測試統編查詢公司名稱，再開立公司統編測試發票。
   - 統編輸入完整 8 碼後應自動查詢，不需另外按查詢按鈕；查詢期間主視窗仍可操作。
   - 再輸入查無資料的 8 碼統編，應提醒「查無此統一編號，請再次確認或自行輸入買方名稱。」右上角保持 API 正常；只有連線、逾時、授權、簽章或服務錯誤才顯示 API 異常。
4. 公司統編切換未稅輸入後，確認未稅銷售額、5% 稅額及含稅總額符合光貿官方公式。
   - 含稅單價 `200` 切成未稅應為 `190.4761905`；切回含稅必須精確顯示 `200`，不得顯示浮點誤差。
5. 同一來源及同一原始訂單編號再次開立時，程式必須阻擋。
6. 模擬網路或回應失敗時，若結果無法確認，清單必須顯示「結果不明，禁止重送」。

## C. MO店+ Excel

1. 匯入一份受密碼保護的 `.xls`，確認 Excel 以唯讀方式開啟且沒有 PowerShell 視窗。
2. 匯入一份 `.xlsx`，確認可依欄名辨識，不依賴檔名或固定欄位位置。
3. 以 MO店+ 原始 `OrderExport` 與光貿官方轉檔結果交叉核對：商品售價為 `120` 時，商品明細仍依官方欄位產生前 6 筆 `113`、後 3 筆 `112`，再列運費 `65` 與滿額免運費 `-65`，發票總額必須為官方的 `1014`。
   - 不得從商品售價、平台淨入帳或預估平台代扣運費重新推算並覆蓋官方開票金額。
   - 原始檔只讀，轉換只存在記憶體，不得留下中介 Excel 或暫存轉檔。
4. 選檔後應立即開啟獨立「MO店+ 開立發票匯入確認」視窗，不得返回主視窗等待；解析、統編查詢及開立中均在該視窗顯示進度。約顯示 10 列並可捲動，每列使用真正 checkbox 取消勾選，整批可取消。
   - 欄位應含訂單編號、統編、買方名稱、課稅別、應稅銷售額、營業稅額、發票總額、項目數及檢查狀態；底部顯示已選張數與已選總額。
   - 公司官方含稅總額 1014 應顯示銷售額 966、稅額 48、總額 1014；送出仍使用官方含稅明細與 DetailVat=1。
5. 公司統編應先找本機人工記憶，沒有才查光貿。光貿成功但名稱空白時，確認視窗必須允許輸入買方名稱；API 技術錯誤只能顯示異常並阻止該列送出，不得當成空名稱。
   - 取消、未勾選、明確失敗或結果不明時，不得寫入人工名稱；成功開立，或結果不明日後查詢確認已開立後，才保存統編對應名稱。
6. 只按「確認開立」才依勾選順序送出。全部成功可關閉視窗；有失敗、結果不明或資料問題時保留視窗並顯示逐列結果，結果不明不可重送。
7. 同一 MO 原始訂單再次匯入時，程式必須阻擋重複開票。
8. 以本次原始檔與光貿轉檔交叉核對：B2C 買方名稱等於收件人，品名接上規格1／規格2，會員載具顯碼與隱碼均為 `motmp_訂單編號`，三項官方金額 500、199、199 加運費 45 及運費補貼 -45 後總額為 898。
9. 測試環境截查 API 請求：OrderId 應依最新定案保留原始訂單編號；BuyerName 必須為「測試消費者」，真實統編、地址、電話、Email、捐贈碼、商品名稱及所有備註不得送入共用測試池；會員載具顯碼／隱碼不得包含原始訂單編號。本機確認畫面及紀錄仍可核對原始資料。

## D. 開立清單與資料保存

1. 清單應明確區分完成、已開立、處理中、需確認、失敗與作廢。
2. 搜尋發票號碼、訂單、買受人、統編、來源或狀態，結果應正確。
3. 按「向光貿更新狀態」後，原送出時間 `SentAt` 不得改變。
   - 更新期間只有該按鈕顯示「重新整理中」，右上角 API 健康燈不得切成查詢中。
   - 已成功開立的發票不得因查詢 `data` 是物件、一層陣列或巢狀陣列而出現 JSON 解碼警告，且不得重送發票。
4. 清單金額以千分位顯示；來源欄須完整顯示 `MO店+`，並保留足以顯示 `好賣+`、`iOPEN` 的固定寬度；訂單編號完整顯示 15 碼 `115102696774269`，統編欄須完整顯示 8 碼統編及 `0000000000`，不得出現省略號。
5. 雙擊任一實際資料列，應開啟該張本機發票的原生唯讀詳細資訊；不得發出 API、修改紀錄或對空白斑馬列產生動作。
6. 關閉再開啟程式，設定、發票紀錄及買受人名稱記憶仍存在。
7. 測試期間備份 `Data` 後刻意損壞 JSON，程式應停止並保留損壞檔，不得以空白資料覆蓋。
8. 同時啟動第二個 `CYInvoice.exe`，應提示程式已在執行並喚回原視窗，不得開啟第二個可操作程序。
9. 模擬光貿成功回覆後本機保存失敗，畫面必須明確顯示遠端已開立、本機保存失敗，且不得提供直接重送；修復本機問題後須以 API 識別資料回復紀錄。
10. 以相同原始訂單測試：現存未作廢發票必須阻擋；舊發票已作廢時，重開送出 API OrderId 應為 `-R2`，再次作廢重開為 `-R3`。回查必須核對發票號碼、銷售額、稅額、總額、DetailVat 及未作廢狀態，不能只比 OrderId。

## E. 介面與酷澎

1. 主畫面在 1180×850 時應與最後正常 V1.0.0 截圖配置一致，設定鈕位於頁籤列右上。程式、工作列與檔案總管的 INV 大小圖示均不得再有右上折角。
2. 視窗可自由放大與最大化；不得縮小至 1180×850 以下，縮放後控制項及清單欄位不得重疊或消失。
3. 已開立發票清單預設日期應為本月第一日至今天。
4. 匯入已驗證的酷澎已寄出 .xlsx，應依欄名辨識並立即進入與 MO店+ 相同的匯入確認視窗，顯示訂單、買家、品項與買家發票總額；不得退回主視窗後才處理。
5. 確認「應開立予酷澎之發票金額」不計入買家發票，同一酷澎訂單成功或結果不明後不可重送。
6. 設定按鈕應固定顯示在頁籤列右上角，按下開啟獨立設定視窗；每次開啟都必須重新輸入管理密碼，取消或關閉不得保留解鎖狀態。
   - 每次開啟設定視窗只顯示管理密碼；密碼正確才顯示完整設定。按取消或關閉視窗後應重新鎖定。
   - 開立頁與清單頁所有文字比前一候選版小一級，普通文字背景必須透明，不得出現白色或灰色矩形底塊。
   - 三個匯入按鈕須為明確的圓角動作按鈕；商品與發票紀錄清單的整個可見資料區須有逐格斑馬紋。已開立清單沒有資料或未滿一頁時也要補滿不可選取、不可雙擊的 UI 空白斑馬列；MO 確認表的實際資料列維持逐格斑馬紋。
   - 商品清單預設完整顯示五列且不得有橫向捲軸；金額欄為灰底唯讀。新增明細不預先驗證，最後開立才移除完全空白列並提示部分填寫列。
   - 商品單價、商品金額、預覽、成功訊息、已開立清單及金額總計皆以千分位顯示；營業稅額、應稅銷售額及發票總額的數值右緣必須對齊。
   - 主頁籤選中項應為深藍粗體文字與藍色底線，不得再出現斜角／梯形；反覆切換時標題文字不得被裁切。切換與鍵盤導覽仍由原生 Tab 處理。
   - 最大化與還原主視窗時，設定按鈕維持固定尺寸並在原生頁籤列內靠右、垂直置中。
   - 商品與已開立清單表頭不得按壓、排序、拖動或拉動欄寬；表頭底線及垂直格線需連續清楚。最後的「操作」／「上傳」後方只能是固定垂直捲軸槽，不得有未命名表頭空白。資料未滿一頁時捲軸停用但位置保留，超過一頁時原地啟用；重新整理不得閃現、消失或造成表頭錯位。
   - 設定視窗完整顯示「MO店+ Excel 保護密碼」；「App Key」位於統編下一列，標籤與「統編」左緣對齊，兩個輸入框左緣也對齊，App Key 使用其餘整列寬度。
7. 啟動及重新檢查 API 時應先顯示灰色「API 查詢中」，成功為綠色「API 正常」，失敗為紅色「API 異常」。
   - 異常時在狀態下方顯示更小的灰字原因；10 秒後重試，期間不得併發產生多筆相同健康檢查 LOG。
   - 測試統編收到 code 99「統一編號格式錯誤」時，因伺服器已收到並解析簽章請求，應顯示 API 正常；簽章或授權錯誤仍應顯示異常。
   - 若先收到 code 15，應由官方 `/json/time` 校時後自動重試一次；成功後清除異常原因。

## F. 發行包

1. 根目錄包含 `CYInvoice.exe`、當版唯一的 `V版本號.txt` 及 `使用說明.txt`。
2. 不得包含 `Version` 資料夾或 `todo.txt`。
3. `Data`、`Cache/InvoicePDF`、`Logs` 目錄均存在。

## 通過條件

- A～D 全部通過，且 `Logs` 沒有未處理的 `ERROR` 或 panic。
- 正式環境不做任何未經確認的實際開票。
- `V1.1.0` 通過本清單與 Windows 實機驗收後才建立正式標籤及 Release；後續測試／小修正推進 PATCH，完整開發階段再推進 MINOR。
