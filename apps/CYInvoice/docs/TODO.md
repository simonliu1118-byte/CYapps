本檔只保留**目前仍未完成、需要後續驗證或尚未取得足夠樣本**的工作。已完成版本內容與歷史決策改由 `CHANGELOG.md`、`MIGRATION_HISTORY.md` 保存，不再把大量已完成事項重複堆在 TODO。

目前正式基準：**CYInvoice V2.4.2 Build 0**  
最新正式 Release：`cyinvoice-v2.4.2`

## 1. V2.5 員工帳戶與作廢流程

V2.5 已完成實作前設計，詳細內容見 `V2_5_EMPLOYEE_VOID.md`。本版目標是先完成**完全不依賴雲端即可運作**的本機員工帳戶與正式發票作廢；雲端同步、Email 密碼重設與 Device Token 等功能延後。

### 第一批：員工核心

- [ ] SQLite 員工 schema／migration。
- [ ] 4 碼唯一員工編號、姓名、Email、Password Hash、啟用狀態、最後修改時間。
- [ ] `SUPER_ADMIN` / `ADMIN` / `EMPLOYEE` 三級權限。
- [ ] 每套本機員工資料只允許一位超級管理員。
- [ ] 底層強制超級管理員不可降級、停用或刪除。
- [ ] 管理員可互相取消對方管理權限，但不得自行降級。
- [ ] 超級管理員高強度復原碼：只存 Hash、一次性使用、成功使用後輪替、可由超管主動重新產生。
- [ ] 不得使用 AMEGO App Key 作為超管復原憑證。

### 第二批：帳戶管理

- [ ] 主畫面加入獨立「帳戶管理」。
- [ ] 只有啟用中的管理員／超級管理員可進入。
- [ ] 新增、修改、停用、一般員工／管理員密碼重設與角色調整。
- [ ] 一般管理員不得直接重設超級管理員密碼。
- [ ] 超級管理員忘記密碼時使用離線復原碼重設；密碼與復原碼同時遺失時不提供一般管理員後門。
- [ ] 舊 CYInvoice 管理密碼僅用於 V2.5 首次遷移，建立第一位超級管理員後退出日常管理機制。
- [ ] 全新安裝直接建立第一位超級管理員並產生復原碼。

### 第三批：AMEGO 作廢核心

- [ ] 實作前重新核對最新光貿 `/json/f0501`、`invoice_query`、`invoice_status` 官方規格。
- [ ] 完整串接／驗證 `/json/f0501` 作廢流程。
- [ ] `CancelReason` 使用「4 碼員工編號 + 空格 + 使用者原因」，原因最多 15 字；實作前再次確認 API 長度限制。
- [ ] 作廢後以官方查詢確認最終狀態，不能只依 `f0501` 初始回覆判定成功。
- [ ] 結果不明、timeout 或官方狀態尚未確認時禁止盲目重送作廢／重開。
- [ ] 作廢後重開仍須維持既有 `-R2`、`-R3` API OrderID 與防重安全語意。
- [ ] 不自行新增本機跨期禁止規則；API 是否允許作廢以 AMEGO 正式結果為準。

### 第四批：員工作廢整合

- [ ] 詳細資料每次開啟都先 `invoice_query`，確認最新狀態後才可進入作廢。
- [ ] 作廢原因輸入最多 15 字。
- [ ] 「發票作廢確認」只保留發票號碼、員工編號、員工密碼三行輸入與責任提示。
- [ ] 發票號碼不得預填；確認視窗不得顯示可照抄的正確發票號碼或完整發票資訊。
- [ ] 發票號碼必須與目前準備作廢的發票完全一致；錯誤只提示不符，不回顯正確答案。
- [ ] 員工不存在、停用或密碼錯誤時不得呼叫 AMEGO。
- [ ] 帳號／密碼錯誤對外使用統一訊息，並加入本機漸進式登入失敗節流。
- [ ] **做到本批 UI 時，必須重新提醒使用者仔細確認責任聲明正式文字、是否需要 Checkbox，以及「已收回證明聯／未收回證明聯」等覆核流程；目前草稿不得直接視為定稿。**

### 第五批：同步與 UI 收尾

- [ ] 作廢時間／`cancel_date` 與作廢狀態納入既有同步更新。
- [ ] 實測送出例如 `3015 退貨` 後的完整 `invoice_query` JSON，確認 AMEGO 是否可查回作廢原因。
- [ ] 若官方 query 不回作廢原因，不為此另外建立永久 `void_audit`。
- [ ] 已開立清單、詳細資訊、PDF／載具預覽與狀態燈號一致顯示作廢結果。
- [ ] 確認作廢後必要 PDF／preview Cache 失效處理。
- [ ] issue center 必要整合；待確認狀態可由啟動同步、5 分鐘同步及手動重新整理再次確認。
- [ ] Windows build、核心測試、startup smoke、工程測試包與實機回歸。

### 明確延後到 V2.5 之後

- [ ] 可選雲端 API 位址。
- [ ] Cloudflare Workers / D1 等免費雲端服務。
- [ ] A/B 機員工同步，本機員工資料作離線 Cache。
- [ ] Email 忘記密碼／驗證碼。
- [ ] Device Token／裝置授權。
- [ ] MO 密碼雲端同步。
- [ ] 多台電腦共用登入失敗計數。

AMEGO App Key 不列入上述雲端化範圍；V2.5 完全維持目前各電腦自行設定、Windows DPAPI 本機保護的既有做法。

## 2. 酷澎樣本補齊

目前已完成已寄出 DeliveryList 的基本解析與開票流程，但以下格式仍缺可靠實際樣本。沒有樣本前維持安全停止，不猜欄位／金額。

- [ ] 未出貨／不同狀態的實際樣本。
- [ ] 公司統編訂單樣本。
- [ ] 多商品訂單樣本。
- [ ] 數量大於 1 的樣本。
- [ ] 折扣／負數調整樣本。
- [ ] 取得樣本後補 parser／金額／防重與測試案例。

## 5. 後續版本原則

- 新功能／修正一律從目前 `main` 的 C#／WinForms 正式線開始，不回到舊 Go／Win32、`cyinvoice/csharp-remake` 或其他歷史 branch。
- 日常修改先依 `REPOSITORY_RULES.md`、`REPO_POLICY.md`、`PROJECT_RULES.md` 執行。
- 正式 Release 只有使用者在當次工作明確要求時才啟動；VERSION／BUILD 推進、PR merge 或工程 Artifact 完成都不等於 Release 授權。
