CYInvoice V3.1.2 Build 2 — 3.2-A 折讓品項編輯與剩餘額守門（engineering／preview）

本版是由 V3.1.1 往下一個獨立 Patch，第一次 CI 測試發現既有人工折讓對帳回歸，依規則同一 Patch 返修為 Build 1；修正歷史查回相容性但維持新官方餘額判定 fail-closed。第二次 CI 發現七位小數測試的固定期望值寫錯，正確 100.1234567÷1.05=95.3556730，依規則改為 Build 2 並重跑精確 head CI；實際 FixedDecimal 運算與含稅/未稅切換保持不變。僅提供工程測試包；上一正式 Release 仍為 V3.1.0。

使用者在發票詳情按「折讓」，程式先執行 AMEGO invoice_query，接著以表格帶入原發票商品。品項可刪除、新增，調整數量、單價與課稅別，保留先前已設計的「以含稅單價輸入」勾選切換；使用者能輸入含稅或未稅單價，不必自己反算，負單價可表達折扣。依原發票 DetailVat 自動帶入正確輸入模式，切換時應稅單價自動換算，免稅／零稅率單價不亂換。含稅輸入由程式用 FixedDecimal 七位小數及整行含稅金額先算未稅金額、稅額，後續 DTO 一律保存光貿所需未稅 UnitPrice／Amount／Tax 並保留原始含稅輸入以供 Core 再驗證。整張含稅折讓總額需為正整數。

invoice_query 的 allowance[] 必須確實出現且為陣列，才能把官方空陣列解釋為沒有已折讓。已完成的有效 D0401/B0401（含相容歷史類型）從原發票含稅金額扣除；有已作廢日期的折讓不再扣除，作廢事件不重複計扣。號碼重複、非認得的紀錄、處理中、金額無法解析等情況停止提交，不假造可折額。已有合法折讓不禁止在剩餘額內再提出另一筆。

員工按提出申請後，原 EmployeeAllowanceWorkflowService 仍重新向光貿查詢官方發票並執行員工身分驗證；對本版編輯器送出的每個草稿品項由 Core 依含稅／未稅輸入模式再次計算未稅／稅額／整張含稅總額，核對官方剩餘額並以不可變明細快照保存在目前本機人工折讓待辦中。舊版人工申請的其他入口仍相容。本版並未啟用 g0401/g0501、正式跨機折讓 API 或自動折讓；正式交易、管理員二次查回與 Cloud 領號在後續 3.2-B～H 才完成。

Windows WinForms smoke 與 Core 合成測試涵蓋已折／取消／處理中／資料缺失、含稅↔未稅來回切換、含稅 105→未稅 100＋稅 5、負數折扣、七位小數及偽造金額拒絕；不以這些隔離結果當作真實光貿折讓成功。原 Cloudflare D1/Worker/Secrets、CYID D1 不操作；需要遷移時須由使用者開本機 Work MCP。V3.0+V3.1 待真人驗收仍沿用 docs/POST_RELEASE_ACCEPTANCE.md。
