### Mobile interaction decisions already made

Preserve these unless the user changes them:

- Entry and ledger are separate mobile pages.
- Ledger is one transaction per row, not card-per-transaction.
- Left swipe reveals Delete; right swipe reveals Edit.
- Swipe itself never performs the destructive/edit action; user must press the revealed action.
- Delete retains confirmation.
- Mobile Edit reuses the main entry form instead of an inline ledger editor.
- Edit button text is `儲存修改`.
- Leaving the entry page before saving an edit means **cancel edit** and no database write.
- In edit mode, the secondary button below Save is `取消`; normal entry mode uses `清空`.
- Cancel returns to the previous ledger month/search/scroll position.
- Successful same-month edit returns to the previous ledger position and briefly highlights the edited row.
- Entry save-success feedback belongs below the Save button and fades after roughly 2.5 seconds; errors remain visible.
- Income/expense presentation uses the stronger Build 3 style four-edge green/red inward gradient; do not revert to a hard border.
- Quick category/summary choices are horizontal chips with stable reserved space.
- Entry field values are visually centered on phone.

## 6. CYID migration constraints that matter for CYACC

When CYID implementation begins, preserve the canonical contract:

- direct Role projection: `SUPER_ADMIN / ADMIN / USER`;
- Identity Admin is an ADMIN capability, not a fourth Role;
- App Access is independent from Workspace Role;
- CYACC remains responsible for accounting/business authorization;
- non-core consumers such as CYACC do not own first-login / new-Employee Email-verification flow;
- normal consumer login uses permanent password only;
- provider Session is the Identity authority;
- do not keep local `web_sessions` as a fallback Identity authority after cutover;
- raw provider Session tokens stay out of JS storage, URLs, logs and business tables;
- Tablet Safari app-specific browser compatibility must be retained until real-device acceptance proves a stricter policy safe;
- password recovery migrates to CYID contract and must not reintroduce account enumeration;
- accounting D1, backup topology, SQLite import, Excel and bookkeeping UI are outside the Identity migration scope.
