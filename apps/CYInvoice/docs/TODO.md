# CYInvoice 待辦與驗證

本檔只保留**目前仍未完成、需要後續驗證或尚未取得足夠樣本**的工作。已完成版本內容與歷史決策改由 `CHANGELOG.md`、`MIGRATION_HISTORY.md` 保存，不再把大量已完成事項重複堆在 TODO。

目前正式基準：**CYInvoice V2.4.2 Build 0**  
最新正式 Release：`cyinvoice-v2.4.2`

## 1. 作廢流程

目前仍未完成完整正式作廢功能，後續實作時必須一次處理完整流程，不以 UI 假完成取代 API 與安全驗證。

- [ ] 完整串接／驗證光貿 `/json/f0501` 作廢流程。
- [ ] 員工帳號／密碼輸入與安全保存／使用方式確認。
- [ ] 作廢原因輸入與必要欄位驗證。
- [ ] 作廢後以 `/json/invoice_status`／`invoice_query` 等官方資料確認最終狀態。
- [ ] 已開立清單、詳細資訊、PDF／載具預覽與狀態燈號一致顯示作廢結果。
- [ ] 跨期作廢限制與錯誤訊息。
- [ ] 作廢後重開仍須維持既有 `-R2`、`-R3` API OrderID 與防重安全語意。
- [ ] 結果不明、timeout 或官方狀態尚未確認時禁止盲目重送作廢／重開。

## 2. 酷澎樣本補齊

目前已完成已寄出 DeliveryList 的基本解析與開票流程，但以下格式仍缺可靠實際樣本。沒有樣本前維持安全停止，不猜欄位／金額。

- [ ] 未出貨／不同狀態的實際樣本。
- [ ] 公司統編訂單樣本。
- [ ] 多商品訂單樣本。
- [ ] 數量大於 1 的樣本。
- [ ] 折扣／負數調整樣本。
- [ ] 取得樣本後補 parser／金額／防重與測試案例。

## 4. V2.4.x 實機回歸紀錄

V2.4.2 已正式 Release。下列項目若沒有另外留下可追溯的實機驗證紀錄，後續維護時仍應保留為回歸清單；**不要因已發布就反推為一定完成**。

- [ ] 以 V2.3.0 真實 `Data` 備份升級到現行 SQLite，確認 DB 建立、舊 JSON 保留、資料筆數與內容一致。
- [ ] 正式環境手動 recent 3-day sync，確認可抓到另一台電腦／光貿端的合法更新。
- [ ] 程式持續開啟超過 5 分鐘，確認啟動同步／排程同步不重疊，手動重新整理維持 30 秒冷卻。
- [ ] 雙擊不同日期的發票，確認每張都先 `invoice_query` 再顯示詳細資訊；query 無法確認時不得把舊 Cache 冒充最新資料。
- [ ] 「上傳問題」／同步問題視窗確認帳號隔離、解決、刪除、重新整理與 Failed 紀錄流程。
- [ ] 測試環境 namespaced OrderID 實機確認：不與共享測試池其他資料撞號，UI 顯示仍維持原始可讀 OrderID。

## 5. 後續版本原則

- 新功能／修正一律從目前 `main` 的 C#／WinForms 正式線開始，不回到舊 Go／Win32、`cyinvoice/csharp-remake` 或其他歷史 branch。
- 日常修改先依 `REPOSITORY_RULES.md`、`REPO_POLICY.md`、`PROJECT_RULES.md` 執行。
- 正式 Release 只有使用者在當次工作明確要求時才啟動；VERSION／BUILD 推進、PR merge 或工程 Artifact 完成都不等於 Release 授權。
