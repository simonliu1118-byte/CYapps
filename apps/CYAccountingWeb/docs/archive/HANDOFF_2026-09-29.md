## 4. Current UI direction and user-approved constraints

The user repeatedly requested one consistent direction: **精緻、商務、簡潔**. Do not regress to dense legacy settings-style UI or oversized explanatory text.

### Desktop (`>=1024px`)

Current stage is based on V0.21.x Desktop Business UI.

Keep these decisions unless the user explicitly changes them:

- Left side = high-speed entry; right side = ledger.
- Approved income/expense segmented slider should not be casually redesigned.
- Approved soft entry-card tints remain:
  - income: pale green;
  - expense: pale red.
- Main section titles `新增記帳` and `記帳資料` should be visually balanced.
- Header high-frequency management entry points are outside Settings: `帳戶管理`, `科目管理`, `設定`, then user/role identity and logout.
- User identity badge distinguishes role visually; SUPER_ADMIN uses subtle gold treatment, ADMIN uses subtle bronze treatment.
- Normal healthy connection status should not consume Header space; only meaningful abnormal status should surface near the app title.
- Ledger month selector uses the custom picker rather than browser-native month UI.
- Desktop date/month/year selection was moved toward custom controls; if any native picker reappears, treat it as a regression and inspect all date/month entry points rather than patching one screen.
- Opening-balance dialog is compact and bound to the currently selected ledger month; title is month-specific and CRUD button text is simply `儲存`.
- Known native `confirm/prompt` flows were replaced by product dialogs during V0.21.1 work. If touching destructive flows, verify no native browser dialog has returned.

### Entry workflow

- Desktop account selection uses buttons, not a select.
- Account button width should follow content; do not force fixed-width grid cells that wrap despite available horizontal space.
- Account name maximum: 8 Chinese characters (server-side validation exists; preserve consistency).
- Summary UI wording: `最多20個字`; underlying validation remains aligned with the desktop accounting rule.
- Amount maximum remains 7 digits (1–9,999,999).
- User-requested Enter flow: **日期 → 摘要 → 金額 → 儲存 → 回到摘要**.
- Plain `Tab` inside entry workflow is used for income/expense switching; do not silently revert to generic focus navigation there.

### Account management

Current direction:

- compact manager, not a large settings page;
- leftmost drag handle for ordering;
- small fixed-width `預設 / 設為預設` tag;
- account name is the primary text;
- rename/edit uses a small controlled editing interaction rather than browser prompt;
- delete remains a clear destructive action;
- optimistic drag: visual order should stay where dropped while persistence runs; only rollback on failure.

The user previously found `設為預設` overflow and inline-edit duplication bugs. V0.21.x contains fixes, but real visual acceptance should still be rechecked if this manager is touched.

### Category management

V0.21.2 deliberately replaced repeated incremental patches with a more compact manager concept:

- top toolbar contains income/expense slider;
- `新增大分類` sits next to the slider;
- `新增科目` is the far-right high-level action;
- adding a category uses a small dialog with group selection + category name instead of repeating an add row under every group;
- main list is for viewing, drag ordering, favorite/common state, rename and delete;
- group/category rename must not explode row height or layout;
- drag ordering and cross-group category movement use the reorder APIs and optimistic UI.

The user declared this area at a temporary stage before the handoff; do not claim final UI acceptance. Continue only after inspecting current production visually.
