# PriceDesk 與 Grok Bot 查價及複審設計

**狀態：設計稿。** 試點商品為 3M 紙膠 **1530-1、1 吋、12 捲／盒**。使用者提供品名、規格與照片，Grok Bot 自行擬定關鍵字，用瀏覽器查 momo 與酷澎台灣，回填每個賣場選項的規格、售價及判讀依據。試點期間，每筆報價由人員複審後才計入行情。本階段範圍為 PriceDesk 與 Grok Bot。

## 商品建檔與派工入口

| 欄位 | 試點設定 |
| --- | --- |
| 品名、型號、尺寸 | 3M 紙膠、1530-1、1 吋 |
| 包裝與我的販售單位 | 每盒 12 捲，以盒販售 |
| 商品照片 | 可附盒身正面、側標或條碼，供型號與規格辨識 |
| 平台與行情 | momo、酷澎台灣；主要比較單盒，延伸查單捲與不同數量的多盒組 |
| 搜尋詞 | 可留給 Grok 自擬；本筆起始詞為「3M 1530-1」 |

新增或編輯商品時按「儲存並交給 Grok 查價」，即可搜尋兩站。既有商品詳情提供「交給 Grok 複查」，可選重新搜尋市場，或只複查勾選的候選。試點正式執行前，先核對原追蹤商品已改為 1530-1；舊型號留下的候選可供回訪，須按新規格重新判讀。

## 任務與 webhook

1. PriceDesk 建立任務，固定本輪使用的商品版本、包裝條件、照片版本、兩個平台和候選範圍。頁面顯示「已派工」。
2. Worker 向指定 Grok routine 的 webhook 發送 HTTPS POST，使用該 routine 的 Bearer 金鑰。收到 HTTP 200 表示已接受觸發。金鑰只由 Worker 使用。
3. Grok 以專屬機器憑證領取任務，讀取公開商品搜尋所需資料與照片限時連結。PriceDesk 顯示「查價中」，分別追蹤兩站進度。
4. Grok 逐筆交回證據。先完成的平台可先複審。離開商品頁後可回到原任務查看、回答或複審。
5. 各平台交回結束狀態後，PriceDesk 分別呈現「完成」「部分完成」「未找到」或「受阻」。結束狀態與人工複審進度分開顯示。

### 喚醒事件

以下編號及資料皆為示例。事件由 PriceDesk 發給 Grok，完整資料由 Grok 回 PriceDesk 領取。

```json
{
  "schemaVersion": 1,
  "event": "pricedesk.task.ready",
  "eventId": "evt-example-001",
  "taskId": "task-example-001",
  "taskVersion": 1
}
```

| 事件 | 附加欄位 | 用途 |
| --- | --- | --- |
| `pricedesk.task.ready` | — | 首次派工 |
| `pricedesk.question.answered` | `questionId` | 讀取答案，接續受影響的查詢 |
| `pricedesk.review.recheck` | `resultId` | 讀取複查原因，重查指定選項 |

重送同一事件沿用原 `eventId`，避免重開工作。派工失敗顯示未送達或送達狀態待確認，保留原任務以供重送。

### PriceDesk 任務接口（擬定）

下列路徑以 `/api/grok/tasks/{taskId}` 為基底。Worker 驗證 Grok 的機器身分及該任務授權。人的派工、回答與複審沿用 PriceDesk 登入身分及操作紀錄。

| 方法與路徑 | 回傳／接收內容 |
| --- | --- |
| GET 基底路徑 | 商品名稱、型號、尺寸、每盒捲數、販售單位、照片限時連結、平台、搜尋或複查模式、候選識別與連結、任務版本、已有問答 |
| POST `/progress` | 平台、執行階段、目前狀態；結束時附實際用過的搜尋詞、完成時間、受阻或部分完成原因 |
| POST `/questions` | `questionId`、任務版本、問題文字、可選答案、受影響候選及相關證據。使用者也可輸入自訂答案 |
| PUT `/results/{resultId}` | 單一賣場選項的辨識結果與報價；以任務版本與結果識別去重。複查帶回新觀測並保留原判讀 |

機器回填只產生待複審資料。已核准結果之後若收到新的價格或規格，另建待審觀測；過期的任務版本不得覆蓋新條件的結論。

## Grok 的搜尋與提問

先從使用者資料與照片辨認商品，再依平台擴詞。例如先查「3M 1530-1」，接著查「3M 紙膠 1吋 12捲」「1530-1 單捲」「1530-1 多盒組」。Grok 可換詞找漏掉型號的刊登，但須用同一組目標條件驗證。

- **momo**：進入原商品頁，實際選取規格、入數及銷售組合後讀價。例如同頁列「1 吋 12 入／半吋 24 入」，必須記錄價格對應哪一個選項。
- **酷澎台灣**：直接搜尋原站，或從飛比候選追到酷澎商品頁。核對實際賣家、規格、選項與價格，只有第三方摘要時保留為參考。
- **需要使用者決定**：若欄位填 1530-1、盒側照片清楚標示 1530-0，在任務頁詢問以哪個為準。回答後從原任務續查。若答案修改目標規格，建立新條件版本。
- **賣場資訊不足**：若賣場只寫「12 入」，看不出是原盒或散裝，先查選項、說明與圖片。仍無法辨識就標為「證據不足」並繼續查其他候選，不要求使用者替賣家猜包裝。
- **平台受阻**：遇登入牆、驗證碼或商品頁無法讀取，回報平台、階段和原因。已完成的平台照常交件。

## Grok 回填格式

以「平台、賣家、原商品、實際銷售選項」為判讀單位。以下 NT$240 為格式示例。

```json
{
  "taskId": "task-example-001",
  "taskVersion": 1,
  "resultId": "result-example-001",
  "platform": "momo",
  "candidateRef": null,
  "listingId": "listing-example",
  "variantId": "variant-example",
  "seller": "範例賣家",
  "productUrl": "https://example.invalid/product/123",
  "selectedOption": "白色 1 吋／12 捲盒裝",
  "observedSpec": {
    "model": "1530-1",
    "widthInches": 1,
    "saleUnit": "box",
    "rollsPerBox": 12,
    "boxesPerOffer": 1,
    "totalRolls": 12
  },
  "offer": {
    "currency": "TWD",
    "totalPrice": 240,
    "availability": "in_stock",
    "priceCondition": "公開售價",
    "checkedAt": "2026-11-27T10:30:00+08:00"
  },
  "classification": "single_box",
  "evidence": "已選取 1 吋盒裝；規格欄列出 1530-1，選取後顯示此價。"
}
```

`candidateRef` 用於回填既有候選。若平台沒有穩定選項編號，保留賣家、原網址與選項原文。可附選取後的證據截圖。缺少的規格或價格填空值，另記原因。整組價和實際購買門檻由 Grok 提供；平均盒價與捲價由 PriceDesk 統一計算。

分類包括單盒（`single_box`）、單捲（`single_roll`）、多盒（`multi_box`）、其他包裝（`other_package`）、不同規格（`different_spec`）及證據不足（`insufficient_evidence`）。同價同標題只能標成疑似重複；核實為同平台、同賣家、同原商品、同選項及同購買門檻，才合併計數。

## 複審與刪除

「Grok 已判讀，待複審」每列直接顯示判定、規格與包裝數量、總價、賣家、證據原文、網址及查詢時間。

| 操作 | 效果 |
| --- | --- |
| 同意 | 核准這個選項與當次報價，符合條件時納入行情 |
| 修正並採用 | 在 Grok 已填資料上改錯的欄位；保存原判與人工結果 |
| 請 Grok 再查 | 附具體原因，例：「請確認此價是否對應 1 吋選項」；只重查指定結果 |
| 刪除 | 從當次待確認清單移除選中的列，可用於停售、下架或本輪無須保留的商品 |

### 刪除只針對當次候選列

在現有待確認表格的「同規格／其他包裝／不是同一商品」後加上「刪除」。商品詳情的候選表沿用同一操作。確認時顯示平台、商品名稱和選項；成功後立即更新該商品的待確認筆數與導覽徽章。

**PriceDesk 不保存刪除名單，不建立排除規則，也不把刪除轉成人工商品判斷。** 下次查價照常從搜尋結果建立候選。停售商品未再出現，自然不會回到清單；若來源再次回傳同一商品，它仍可重新成為候選。操作依現有機制寫稽核，稽核不參與候選篩選。

以所選列的識別與當輪資料版本定位，不按標題或價格批次刪除。若清單已換成新一輪，提示重新整理。對舊候選的晚到複查結果只能更新仍存在的原列，不能憑回報重新插入剛移除的列。刪除待確認列不連帶刪除歷史價格。

## 行情呈現

商品頁先列「3M 1530-1｜1 吋｜12 捲／盒」、兩站各自的查詢時間與狀態，優先呈現單盒價。初期只統計已複審且當次可購買的同條件公開報價。

| 區塊 | 收錄及呈現 |
| --- | --- |
| 單盒行情 | 1 盒、盒內 12 捲。各平台分列最低盒價、中位盒價與有效報價數，可展開各賣家與選項 |
| 單捲行情 | 可單買 1 捲的實售價。可另顯示「以單捲價買 12 捲」試算，與盒裝報價分列 |
| 多盒行情 | 依實際門檻列 2 盒、3 盒、10 盒等組價，顯示整組總價與平均每盒。購物車可選 10 件但無組合或優惠時，不登記為十盒組優惠 |
| 其他包裝或證據不足 | 12 捲散裝、缺貨、僅有最低起價、選項價格不明等，保留原因與原頁。會員、券後、滿額等條件另行標示 |

查完未找到某一包裝時，顯示「本次未找到」。整站受阻時顯示「平台受阻」。所有已採用的報價都能追到賣家、選項、原頁、觀測時間及實際購買量。

## 試點驗收

1. 儲存 1530-1 試點並派工，Grok 能讀到 1 吋、12 捲／盒及這一版照片。重送同一 webhook 不重開任務。
2. momo 同頁含半吋與 1 吋時，回填被選取的規格與對應價格。酷澎重複候選核對原頁後才合併。
3. 需要使用者定案時，問題與答案留在原任務。平台受阻或賣場資訊不足時，仍能交回其他平台與候選。
4. 核准單盒、單捲和 10 盒組各一筆，三筆分別進入正確區塊；十盒組平均盒價等於實售總價除以十。退回及未審結果不進入統計。
5. 假設有 18 筆待確認，刪除其中一列後，在沒有其他變動下，列表及徽章都顯示 17 筆。同名鄰列、歷史報價不受影響。
6. 再跑一輪查價：來源未回傳已刪商品時維持缺席；若再次回傳則可重新入列。測試須涵蓋同輪晚到回報與下一輪新候選兩種情況。
