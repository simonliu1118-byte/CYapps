# CYInvoice Windows 候選版驗證清單

本清單供現行 C#／WinForms 正式線的候選工程測試包執行聚焦驗收。所有開票測試先使用光貿測試環境；只有使用者明確指定的正式驗證才可切換正式公司環境。

## A. 全新啟動與安全設定

1. 將候選版解壓縮到全新資料夾，確認原本沒有 `Data/settings.json`。
2. 啟動 `CYInvoice.exe`，應強制顯示「首次安全設定」。
3. 關閉或取消首次設定時，程式應直接結束，不得略過設定進入主畫面。
4. 管理密碼或 MO店+ Excel 密碼任一留白，應拒絕儲存。
5. 輸入 MO店+ Excel 密碼與兩次相同的管理密碼後才可完成；首次環境固定為光貿測試。
6. Enter 順序固定為「MO店+ Excel 密碼 → 管理密碼 → 再次輸入管理密碼」，只有最後一欄 Enter 才直接完成設定。
7. 關閉後重新啟動，首次設定視窗不應再次出現。
8. `Data/settings.json` 不得出現 App Key、MO 密碼或管理密碼明文。

## B. 手動開立與買方名稱

1. 使用自動訂單編號，確認格式為 `MYYYYMMDDXXX`，再開立一般消費者測試發票。
2. 一般消費者固定含稅；統編／買方名稱欄位保持停用外觀。
3. 切換公司統編後輸入合法 8 碼統編：
   - 第 8 碼輸入完成即自動查詢，不需離開欄位。
   - 查詢期間主視窗仍可操作。
   - 買方名稱欄位外框、高度、Margin 與統編 TextBox 一致，不得因 `↻` 被撐大或裁切。
4. 人工把買方名稱改成與 API 名稱不同：
   - 名稱應顯示不一致提示／紅字。
   - 欄位右側顯示內嵌 `↻`；符號需視覺置中、與輸入框邊緣保留留白。
   - 滑鼠移到 `↻` 上使用手形點選游標，不得顯示文字輸入游標。
   - 點 `↻` 後直接重查 API、繞過本機人工記憶；有 API 名稱時更新欄位並清除不一致狀態。
5. 快速連續輸入不同統編時，較早的非同步查詢結果不得覆蓋目前最新統編。
6. 光貿正常回覆但查無名稱時允許人工輸入；連線、逾時、授權、簽章或服務錯誤不得當成「查無名稱」。
7. 公司統編切換未稅輸入後，驗證固定精度：含稅 `200` → 未稅 `190.4761905` → 含稅 `200`。
8. 商品明細品名 Enter → 數量 → 單價；單價 Enter 後，有下一列就移至下一列品名，沒有則新增列並移至新品名。
9. 同一來源＋原始訂單再次開立必須阻擋；結果不明時禁止重送。

## C. MO店+ Excel

1. 匯入受密碼保護 `.xls`，確認 Excel COM 唯讀開啟且沒有 PowerShell 中介。
2. 匯入 `.xlsx`，確認依欄名辨識，不依檔名或固定欄位位置。
3. 以既有實際樣本核對官方開票金額：`6×113 + 3×112 + 65 - 65 = 1014`，不得用商品售價或平台淨入帳覆蓋。
4. 選檔後立即開啟匯入確認視窗；解析、統編查詢、勾選與開立進度都在該視窗內完成。
5. 公司官方含稅總額 1014 顯示為銷售額 966、稅額 48、總額 1014；送出仍保持既有含稅明細與 DetailVat 規則。
6. 取消、未勾選、明確失敗或結果不明時，不得寫入人工買方名稱；成功或日後嚴格確認已開立後才可保存。
7. 測試環境不得把真實客戶資料、商品文字或聯絡資料送入共用測試池。

## D. 酷澎與鼎新 ERP

### D1. 酷澎

1. 匯入已驗證的已寄出 DeliveryList `.xlsx`，依欄名辨識並進入共用確認視窗。
2. 使用「應開立予買家之發票金額」；不得把「應開立予酷澎之發票金額」加到買家發票。
3. 尚未取得可靠樣本的特殊格式必須安全停止，不猜測。

### D2. 鼎新 ERP

1. 匯入實際鼎新 `.xlsx`；檔案選擇器顯示一般 Excel 檔案，不使用誤導性的「標準 Excel」名稱。
2. 必須找到「單頭資料」與「單身資料」，且一個活頁簿只允許一張銷貨單。
3. 單頭必要欄位：銷貨單號、客戶全名、統一編號、本幣合計；單身必要欄位：品名、數量、金額。
4. 若單身有「單位」，匯入後對應商品項目的 Unit；沒有單位欄仍可正常處理。
5. 單價以 `金額 ÷ 數量` 推導；負數折扣列保持一般明細。單身金額合計不等於單頭本幣合計時必須停止。
6. 公司統編匯入後，第 8 碼完整時使用與手動畫面**同一套**自動查詢／名稱基準／`↻` 重查行為。
7. 確認列的「統一編號」Label／TextBox、「買方名稱」Label／TextBox、「套用資料」及右側提示文字必須在同一條垂直中心線。
8. 原始鼎新統編／客戶名稱只作核對，不隨人工修改改寫；文字過長時可透過提示查看完整內容。
9. 修改統編或買方名稱後必須先按「套用資料」；未套用前不得開立。
10. 統編與買方名稱只能同時有值或同時空白；兩欄只填一欄必須阻擋。
11. 檢查狀態應使用直接文字，例如「可開立」、「已有開立紀錄，禁止重送」、「開立結果待確認，禁止重送」。
12. 鼎新一律紙本；消費者統編空白時不得把原始客戶名稱當公司名稱送出。

## E. 已開立清單、狀態與資料保存

1. 清單應明確區分完成、已開立、處理中、需確認、失敗與作廢。
2. 日期、發票號碼、訂單、買受人、統編、來源、發票狀態篩選必須正確；來源可選鼎新 ERP。
3. 兩排篩選欄位的 Label、DateTimePicker、TextBox、ComboBox 各自在同一條垂直中心線；日期區的「至」也需置中。
4. 單擊發票號碼可複製並顯示短暫完成提示。
5. 重新整理狀態不得改寫 `SentAt`，不得因 API 回覆格式差異重送發票。
6. 雙擊實際資料列開啟詳細資訊；空白斑馬列不可選取、不可雙擊、不可寫進本機資料。
7. 同來源原始訂單：現存未作廢發票必須阻擋；作廢後重開 API OrderId 依序為 `-R2`、`-R3`。
8. 模擬 AMEGO 成功、本機保存失敗時，必須明確表示遠端已開立／本機保存失敗並禁止直接重送。
9. 備份 `Data` 後刻意損壞 JSON，程式應停止並保留損壞檔，不得用空白資料覆蓋。
10. 同時啟動第二個 `CYInvoice.exe` 應被單一程序鎖阻擋。

## F. PDF、詳細資訊與直接列印

1. 準備一般消費者紙本、公司統編紙本、會員載具各一張。
2. 紙本詳細資訊自動顯示官方 A4 style 0 第一頁預覽；完整 PDF 有第二頁時，預覽只能顯示第一頁但原始 PDF 不得被改寫。
3. 同日重新開啟同一張時沿用有效 `InvoicePDF`／`InvoicePreview` Cache；隔日重新取得。損壞 PDF／PNG 必須重建。
4. 一般消費者「檢視 PDF」直接開 A4；公司統編先顯示五張去識別化卡片：A4 整張、A4（地址＋A5）、A4（A5 內容）、A5、QRcode_A4，選定後才取得真實 PDF。
5. PDF Viewer 不顯示 CYInvoice 自製縮放列；使用 Edge PDF Viewer 原生工具列測試縮放、下載與手動列印。
6. 「列印發票」直接使用官方 PDF 並送到 CYInvoice 記住的發票印表機，不開啟可見 PDF Viewer，也不得修改 Windows 全域預設印表機。
7. 印表機選擇只列出 Windows 回報支援雙面的印表機；一般消費者固定 A4、雙面、長邊翻轉。公司統編先選版型，再使用記住的印表機與其 duplex 設定。
8. 記住的印表機不存在或不再支援雙面時，必須要求重新選擇，不得偷偷改送 Windows 預設印表機。
9. 會員載具不得呼叫 `invoice_file`、不得建立紙本 PDF／PNG Cache、不得顯示一般紙本列印按鈕；模擬票面需清楚標示非正式憑證且不可承載正式驗證資料。
10. 關閉 PDF 視窗後主程式仍可操作；主程式結束後，本次 WebView2 子程序應結束。

## G. UI 與主視窗

1. 主視窗一般狀態維持正式預設尺寸；最大化、最小化、還原後控制項不得重疊或消失。
2. 設定按鈕固定在頁籤列右上角，尺寸不隨最大化比例放大。
3. 商品與已開立清單不得出現水平 scrollbar 或未命名假欄位；系統垂直 scrollbar 槽保持固定。
4. 主視窗最下方右側顯示低調灰色 `Copyright © 2026 C.C. Liu, Chihyuan Co. All Rights Reserved.`，不得搶過主要操作資訊。
5. 三個匯入按鈕、頁籤、表格、文字背景與金額顯示維持既有 V2 正式視覺，不因局部修正加入第二套 layout/state 路徑。

## H. 發行包

1. 根目錄包含 `CYInvoice.exe`、當版唯一 `V版本號.txt` 及 `使用說明.txt`。
2. 不得包含 `Version` 資料夾或 `todo.txt`。
3. 套件第一次啟動後由程式建立 Data／Cache／Logs；正式 ZIP 不依賴空資料夾 entry。
4. 工程 Artifact 版本文字包含 `Channel: engineering`；正式 ZIP 包含 `Channel: formal`。
5. WebView2 managed DLL 集中於 `Runtime/WebView2`；根目錄不得殘留開發用 WebView2 XML 說明檔。
6. 正式 Release 必須由 `main` 重新執行核心測試、WinForms startup smoke、公開安全掃描、Windows x64 build、PE／package 驗證、portable smoke 與 SHA-256。

## 通過條件

- A～H 對本次變更涉及的範圍全部通過，且 `Logs` 沒有未處理的 `ERROR` 或未處理例外。
- 正式環境不做任何未經使用者確認的實際開票。
- 發票成功判定、防重、環境隔離、結果不明禁止重送等安全不變量不得因 UI／文件調整而改變。
- 未來 `/json/invoice_list` 自動同步與 SQLite 遷移目前仍是後續規劃，不列為 V2.3.0 現行 RC 通過項目。
